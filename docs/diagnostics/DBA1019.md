# DBA1019：ValueObject 不得參考 Entity

## 目的與預設嚴重性

明確選用 ddd Profile 後，限制 VO 的宣告 instance 狀態持有 Entity。預設 Warning；與 DBA1018 分開啟用及調整。

## 適用範圍與觸發條件

VO 與 Entity／Aggregate 必須具有精確內建或明確 mapping 證據。檢查 instance property／field、繼承成員、array、已知 enumerable／collection／dictionary key/value、tuple、nullable、nested container 與 generic constraint。來源內可解析的 wrapper 依實際宣告成員追蹤，診斷包含成員／元素路徑。

共同設定、權威與角色優先序見 [Analyzer 採用政策](../product/analyzer-policy.md)。

## 違規範例

```csharp
using ArchPrecept.Contracts.Domain;
public sealed class Order : AggregateRoot<System.Guid> { }
public sealed record OrderReference(Order Entity) : IValueObject;
```

## 合規範例

```csharp
using ArchPrecept.Contracts.Domain;
public readonly record struct EntityId(System.Guid Value) : IValueObject;
public sealed record OrderSnapshot(string Name, decimal Amount) : IValueObject;
```

## 修正指引

保存 ID、必要純量或不可變 snapshot；不要把 Domain Entity 藏在 List、Dictionary value 或 readonly field 中。若型別其實不是 VO，先檢查 mapping 的適用性。

## 已知限制與例外

未知 generic wrapper 的型別引數不證明實際持有；metadata-only wrapper、object／dynamic、無約束 generic、循環與深度界線回報 DBA0002。不以名稱含 Entity／Snapshot 推定角色。只分析宣告狀態，不追蹤方法參數、任意 runtime 物件圖或 reflection。generated code 排除。

## 設定與 Suppression

```xml
<ArchPrecept version="1" profiles="ddd">
  <Rule id="DBA1019" severity="error" />
</ArchPrecept>
```

自有契約可分別設定 value-object、entity、aggregate mapping；Analyzer-only 不需要 Contracts runtime。標準 Roslyn severity 最後套用，Rule enabled=false 可明確停用。
