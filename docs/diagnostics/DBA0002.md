# DBA0002：宣告範圍與未評估狀態

## 目的與預設嚴重性

提供可讀與機器可讀的評估範圍。預設 Info；不是規則通過證明，也不預設阻擋 build。

## 設計理由與取捨

本項是產品的[覆蓋資訊與結論契約](../product/rule-design-rationale.md#evidence)，不把架構方法論當作檢查已完成的證據。角色未辨識、規則停用或局部型別無法分析時，必須與違規及通過結論分開，避免零 Diagnostic 造成錯誤信心。

代價是需保存並合併範圍、違規與載入狀態；Info 也可能需要輸出策略才能留存。applicable 只說明適用條件，不證明規則執行、執行期行為或完整合規；局部 not-evaluated 不能被同一型別的一般 applicable 抵銷。

## 適用範圍與觸發條件

Expected 明確指定型別與角色時，逐規則回報 applicable／disabled／not-applicable／not-evaluated。缺少角色、型別無法唯一取得、generated／metadata-only 型別或無效設定會給原因。VO 檢查遇到 object、dynamic、未知 metadata wrapper、無約束 generic、循環或深度上限，也對具體成員回報 not-evaluated。

共同設定、權威與角色優先序見 [Analyzer 採用政策](../product/analyzer-policy.md)。

## 違規範例

```xml
<ArchPrecept version="1" profiles="core" namingConventions="false">
  <Expected type="My.Application.MissingOperation" role="use-case" />
</ArchPrecept>
```

型別不存在會是 not-evaluated，不是成功。

## 合規範例

```xml
<ArchPrecept version="1" profiles="framework" namingConventions="true">
  <Expected type="My.Application.SaveUseCase" role="use-case" />
</ArchPrecept>
```

存在且可辨識的來源型別可回報 applicable，但仍須合併所有違規與編譯結果判讀。

## 修正指引

依 reason 補齊 mapping、修正型別 metadata 名稱，或確認停用／排除是刻意政策。一般 helper 不需要全部列為 Expected。

## 已知限制與例外

applicable 只代表角色、設定及宣告形狀符合規則適用條件，不宣稱規則已執行，不證明 runtime 行為、deep immutability 或完整架構合格。VO 的局部未知結果優先於同一型別的一般 applicable 訊息；必須合併同一 rule/type 的全部結果。命令列建置可能省略 Info，包含 SARIF；如需覆蓋報告，先將 DBA0002 severity 設為 warning，再產生 SARIF。

## 設定與 Suppression

```ini
[*.cs]
dotnet_diagnostic.DBA0002.severity = warning
```

用 `dotnet build -p:ErrorLog=diagnostics.sarif` 取得 type、role、ruleId、diagnosticId、status、reason、roleEvidence 與 confidence。停用它會失去覆蓋訊息，不等於修正未評估範圍。
