# DBA1014：Controller 必須依賴 Use Case 邊界

## 目的與預設嚴重性

`DBA1014` 防止 Controller 直接注入會繞過 Use Case 邊界的相依項目。Roslyn
Descriptor 的正式標題為 `Controller must depend on a Use Case boundary`，分類為
`Architecture`。

| 欄位 | 值 |
|---|---|
| Diagnostic ID | `DBA1014` |
| 預設 severity | `Error`（`DiagnosticSeverity.Error`） |
| 預設啟用 | 是 |
| 產生位置 | 違規建構函式參數的位置 |

## 適用範圍與觸發條件

此規則由 `ControllerComplianceAnalyzer` 在 C# 的類別宣告上執行；產生的程式碼
不會被分析。下列全部前提成立時，才會檢查相依項目：

1. 類別的簡單名稱以區分大小寫的 `Controller` 結尾。
2. 類別不是 `abstract`。
3. 分析器逐一檢查該類別每個 instance constructor 的每個參數。

只要參數型別的簡單名稱符合下列任一條件，就會對該參數回報一個 `DBA1014`：

| 判定 | 精確條件 |
|---|---|
| Handler | 名稱以 `Handler` 結尾 |
| Bus／Mediator／Dispatcher | 名稱正好是 `IMessageBus`、`IMediator` 或 `IDispatcher`；或以 `Dispatcher` 結尾 |
| Domain Service | 名稱以 `DomainService` 結尾 |
| 寫入／一般 Repository | 名稱以 `Repository` 結尾，且名稱**不**以 `QueryRepository` 結尾，並且其所有實作介面中沒有簡單名稱為 `IQueryRepository` 的介面 |

此規則不以 `[ApiController]` 是否存在作為前提；缺少該 Attribute 會由另一條
`DBA1004` 另行回報。多個違規建構函式參數會各自產生診斷。

## 違規範例

```csharp
using System;

public sealed class ApiControllerAttribute : Attribute { }
public interface IMessageBus { }

[ApiController]
public sealed class OrdersController
{
    // DBA1014：IMessageBus 是禁止的 Controller 相依項目。
    public OrdersController(IMessageBus bus) { }
}
```

## 合規範例

```csharp
using System;

public sealed class ApiControllerAttribute : Attribute { }
public interface ICreateOrderUseCase { }

[ApiController]
public sealed class OrdersController
{
    public OrdersController(ICreateOrderUseCase useCase) { }
}
```

明確的純查詢端點也可使用名稱以 `QueryRepository` 結尾、或實作
`IQueryRepository` 的查詢 Repository；這是本規則明確實作的例外。

## 修正指引

1. 將 Handler、Bus、Mediator、Dispatcher、Domain Service 或一般 Repository 的
   建構函式相依，替換為代表工作流程的 Use Case 介面。
2. 將訊息派送、處理器協調與領域服務呼叫移入 Use Case 或其下游實作，而不是在
   Controller 直接處理。
3. 若端點確實是純查詢，使用明確的查詢 Repository 契約；不要僅為避開檢查而以
   名稱偽裝寫入 Repository。
4. 修正後重新建置，確認同一個 Controller 不再對每個建構函式多載重複回報。

## 已知限制與例外

- 判定完全依賴型別簡單名稱與 `IQueryRepository` 介面名稱，不驗證命名空間、
  實際架構角色或是否真的呼叫 Use Case。
- 這是禁止清單，不會驗證剩餘相依是否真的為 Use Case；例如不符合禁止條件的
  任意型別不會由 `DBA1014` 回報。
- 規則只檢查 constructor parameter，不檢查欄位、屬性、方法參數、Service
  Locator 或執行期工廠解析。
- `abstract` Controller 與產生的程式碼會被略過。
- Controller 內直接建立 `Handler`／`UseCase`、或直接存取 `DbContext`／
  `SaveChanges`，分別由 `DBA1006` 與 `DBA1005` 處理，不是本規則的範圍。

## 設定與 Suppression

目前實作不讀取自訂 `AnalyzerConfigOptions`、Additional File 或每個型別的設定；
可用標準 Roslyn／MSBuild 診斷設定調整嚴重性。例如在 `.editorconfig` 中停用此
規則：

```ini
[*.cs]
dotnet_diagnostic.DBA1014.severity = none
```

若必須處理已審查的局部例外，將 suppression 限縮在最小程式碼範圍，並在註解中
留下理由：

```csharp
#pragma warning disable DBA1014 // 已核准的相容層；待移轉至 ICreateOrderUseCase。
public OrdersController(LegacyOrderHandler handler) { }
#pragma warning restore DBA1014
```

優先修正邊界；不要以專案全域停用取代架構決策。

  的 `ControllerForbiddenDependency`。
- 現有合規測試：
  `ControllerComplianceAnalyzerTests.Allows_injected_use_case_interface_in_controller`，
  以及 `Allows_query_repository_for_explicit_pure_query_profile`。
- 現有違規測試：
  `ControllerComplianceAnalyzerTests.Reports_injected_handler_in_controller`，
  以及 `Reports_message_bus_injection_in_controller`。

上述測試覆蓋 Handler、`IMessageBus` 與查詢 Repository 例外；其餘名稱式分支的
精確行為以目前實作為準。
