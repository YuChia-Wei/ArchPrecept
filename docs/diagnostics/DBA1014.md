# DBA1014：Controller 必須依賴 Use Case 邊界

## 目的與預設嚴重性

`DBA1014` 防止 Controller 直接注入會繞過 Use Case 邊界的相依項目。Roslyn
Descriptor 的正式標題為 `Controller must depend on a Use Case boundary`，分類為
`Architecture`。

| 欄位 | 值 |
|---|---|
| Diagnostic ID | `DBA1014` |
| 預設 severity | `Error`（`DiagnosticSeverity.Error`） |
| 預設啟用 | 是 |
| 產生位置 | 違規建構函式參數的位置 |

## 設計理由與取捨

[Controller 與應用編排分責](../product/rule-design-rationale.md#http)使 HTTP 入口可重用同一 Use Case。產品預設要求 Controller 經 Use Case，禁止直接注入 Handler、Bus、領域服務與寫入 Port；成本是簡單端點也可能需要一個小型應用邊界。

只有明確選定的純查詢端點可直接用窄 Query Repository／Service，此路徑允許但不鼓勵。現版 query-role 豁免沒有端點層級明選判定，也不證明實際無副作用；帶寫入能力的完整 Adapter 不應因同時有 query 角色就取得政策豁免。

## 適用範圍與觸發條件

檢查已辨識為 controller 的非抽象 class／record 之 instance constructor parameters。Handler、bus、domain-event-dispatcher、domain-service，或非 query-repository 的 repository 相依會回報。純 query-repository 是本規則的保留例外；團隊仍須自行確認該端點的純查詢政策。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。目前未設定時採 `legacy`，以下名稱式範例以此預設為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

```csharp
using System;

public sealed class ApiControllerAttribute : Attribute { }
public interface IMessageBus { }

[ApiController]
public sealed class OrdersController
{
    // DBA1014：IMessageBus 是禁止的 Controller 相依項目。
    public OrdersController(IMessageBus bus) { }
}
```

## 合規範例

```csharp
using System;

public sealed class ApiControllerAttribute : Attribute { }
public interface ICreateOrderUseCase { }

[ApiController]
public sealed class OrdersController
{
    public OrdersController(ICreateOrderUseCase useCase) { }
}
```

明確的純查詢端點也可使用名稱以 `QueryRepository` 結尾、或實作
`IQueryRepository` 的查詢 Repository；這是本規則明確實作的例外。

## 修正指引

1. 將 Handler、Bus、Mediator、Dispatcher、Domain Service 或一般 Repository 的
   建構函式相依，替換為代表工作流程的 Use Case 介面。
2. 將訊息派送、處理器協調與領域服務呼叫移入 Use Case 或其下游實作，而不是在
   Controller 直接處理。
3. 若端點確實是純查詢，使用明確的查詢 Repository 契約；不要僅為避開檢查而以
   名稱偽裝寫入 Repository。
4. 修正後重新建置，確認同一個 Controller 不再對每個建構函式多載重複回報。

## 已知限制與例外

這是禁止清單，不保證其餘相依必為 UseCase，也不證明 Controller 實際呼叫 UseCase。Query 例外的適用決策仍由採用者負責；欄位、屬性與 action parameter 注入不在此 constructor 規則範圍。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1014.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1014`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
