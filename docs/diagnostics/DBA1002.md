# DBA1002：Use Case 或 Handler 不應注入 IServiceProvider

## 目的與預設嚴重性

此規則禁止 Use Case 或 Handler 透過 `IServiceProvider` 採取 Service Locator 模式。相依應以具名、可檢視且可測試的建構式或成員型別宣告。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1002` |
| Descriptor 標題 | `Use case or handler should not inject IServiceProvider` |
| 類別 | `Architecture` |
| 預設嚴重性 | `error` |
| 預設啟用 | 是 |

## 適用範圍與觸發條件

檢查已辨識為 use-case 或 handler 的 class／record／struct 之直接欄位、屬性及方法／建構函式參數；型別為 `System.IServiceProvider` 時回報。介面的 UseCase 形狀由 DBA1015 處理，本規則不分析介面成員的服務提供者注入。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。未設定時採 legacy，以下名稱式範例以此相容模式為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

```csharp
using System;

public sealed class PlaceOrderHandler(IServiceProvider serviceProvider)
{
}
```

上述 primary constructor 的 `serviceProvider` 會觸發 `DBA1002`。

## 合規範例

```csharp
public interface IOrderRepository { }

public sealed class PlaceOrderHandler(IOrderRepository repository)
{
}
```

此例明確宣告所需的相依，沒有讓 Handler 在執行期以 `IServiceProvider` 查找服務。

## 修正指引

1. 找出實際以 `GetService`／`GetRequiredService` 取得的每一個服務。
2. 將必要服務改成具體抽象型別的建構式參數，例如 Repository、Domain Service 或 Application Port。
3. 對具有條件式選擇的服務，優先注入明確的 factory、策略集合或領域抽象，而非注入容器本身。
4. 將 DI 註冊保留在 composition root；Use Case 與 Handler 只描述自身所需的相依。

## 已知限制與例外

不分析方法內部的任意服務查找流程或完整相依圖。低信心命名模式仍可能將同名 helper 納入，採用者可關閉 namingConventions 並使用明確 mapping。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1002.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1002`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
