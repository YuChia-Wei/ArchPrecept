# DBA1002：Use Case 或 Handler 不應注入 IServiceProvider

## 目的與預設嚴重性

此規則禁止 Use Case 或 Handler 透過 `IServiceProvider` 採取 Service Locator 模式。相依應以具名、可檢視且可測試的建構式或成員型別宣告。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1002` |
| Descriptor 標題 | `Use case or handler should not inject IServiceProvider` |
| 類別 | `Architecture` |
| 預設嚴重性 | `error` |
| 預設啟用 | 是 |

## 適用範圍與觸發條件

分析器只分析 C# 來源中的 class，且不分析產生的程式碼。class 名稱必須以大小寫相符的 `UseCase` 或 `Handler` 結尾；namespace 與實作的介面不影響此判斷。

在符合名稱條件的 class 中，只要下列任一直接成員的型別經語意解析為 `System.IServiceProvider`，就會回報 `DBA1002`：

- 欄位型別；
- 屬性型別；
- 任一方法的參數型別，包含一般方法、建構式與 C# primary constructor 的參數。

介面即使名稱以 `UseCase` 結尾，也不會由此規則檢查 `IServiceProvider`；同一個分析器可能仍以其他 Diagnostic 檢查該介面的 Use Case 形狀。

## 違規範例

```csharp
using System;

public sealed class PlaceOrderHandler(IServiceProvider serviceProvider)
{
}
```

上述 primary constructor 的 `serviceProvider` 會觸發 `DBA1002`。

## 合規範例

```csharp
public interface IOrderRepository { }

public sealed class PlaceOrderHandler(IOrderRepository repository)
{
}
```

此例明確宣告所需的相依，沒有讓 Handler 在執行期以 `IServiceProvider` 查找服務。

## 修正指引

1. 找出實際以 `GetService`／`GetRequiredService` 取得的每一個服務。
2. 將必要服務改成具體抽象型別的建構式參數，例如 Repository、Domain Service 或 Application Port。
3. 對具有條件式選擇的服務，優先注入明確的 factory、策略集合或領域抽象，而非注入容器本身。
4. 將 DI 註冊保留在 composition root；Use Case 與 Handler 只描述自身所需的相依。

## 已知限制與例外

- 角色判定完全依 class 名稱後綴；不以 namespace、介面實作或 attribute 判定。因此命名相符但非真正 Use Case／Handler 的類別可能被檢查，而不相符的實作不會被檢查。
- 規則僅檢查直接欄位、屬性與方法參數。它不追蹤方法回傳值、區域變數、泛型包裝型別、繼承鏈，或 `IServiceProvider` 取得後的實際 `GetService` 呼叫。
- `ServiceLocator` 型別、`[Inject]`／`[FromServices]` 屬性注入等其他 Service Locator 型態由 `DBA1010` 處理，不應誤認為本規則的涵蓋範圍。
- 沒有程式碼層級的白名單或規則專屬例外。僅在外部框架簽章無法改變且已記錄理由時，使用範圍最小的 suppression。

## 設定與 Suppression

目前沒有 `DBA1002` 專屬設定鍵。以 Roslyn 嚴重性設定控制採用端行為：

```editorconfig
[*.cs]
dotnet_diagnostic.DBA1002.severity = error
```

短暫且有追蹤項目的例外可使用：

```csharp
#pragma warning disable DBA1002 // 外部框架簽章；追蹤項目：<id>
public sealed class LegacyHandler(IServiceProvider serviceProvider) { }
#pragma warning restore DBA1002
```

`none`、`silent`、`suggestion`、`warning` 與 `error` 都是可用嚴重性值；對核心 Application 邊界，預設範本維持 `error`。
