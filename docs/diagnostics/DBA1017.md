# DBA1017：派送 Handler 必須轉接至一個 Use Case

## 目的與預設嚴重性

`DBA1017` 限制 Command／Query 派送 Handler 的相依邊界：它必須辨識到剛好一個
Use Case，且不可直接依賴 Repository 或 Domain Service。Roslyn Descriptor 的正式
標題為 `Dispatch Handler must adapt to one Use Case`，分類為 `Architecture`。

| 欄位 | 值 |
|---|---|
| Diagnostic ID | `DBA1017` |
| 預設 severity | `Error`（`DiagnosticSeverity.Error`） |
| 預設啟用 | 是 |
| 產生位置 | Handler 類別的宣告位置 |

## 適用範圍與觸發條件

檢查已辨識為 dispatch-handler 的 class／record／struct（包含 abstract）。彙整 instance constructor 與直接方法參數，辨識出的不同 use-case 型別必須剛好一個；參數亦不得為 repository 或 domain-service。每個條件獨立回報；一般 handler 若未辨識為 dispatch-handler，則不套用此薄 adapter 慣例。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。未設定時採 legacy，以下名稱式範例以此相容模式為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

```csharp
using System.Threading;
using System.Threading.Tasks;

public interface IPlaceOrderUseCase
{
    Task ExecuteAsync(CancellationToken cancellationToken);
}

public interface IOrderRepository { }

public sealed class PlaceOrderCommandHandler
{
    // DBA1017：雖有一個 Use Case，仍不可直接依賴 Repository。
    public PlaceOrderCommandHandler(
        IPlaceOrderUseCase useCase,
        IOrderRepository repository) { }
}
```

## 合規範例

```csharp
using System.Threading;
using System.Threading.Tasks;

public interface IPlaceOrderUseCase
{
    Task ExecuteAsync(CancellationToken cancellationToken);
}

public sealed class PlaceOrderCommandHandler
{
    public PlaceOrderCommandHandler(IPlaceOrderUseCase useCase) { }
}
```

## 修正指引

1. 將 Handler 調整為恰好辨識一個 `*UseCase` 相依，並將 Command／Query 的輸入
   轉為該 Use Case 所需的輸入。
2. 移除 Handler 直接注入的 `*Repository` 與 `*DomainService`；將資料與領域工作
   放入 Use Case 及其下游協作者。
3. 若一個 Handler 同時協調多個 Use Case，將協調責任移至一個明確的上層 Use Case
   或重新拆分派送邊界。
4. 修正後確認不只存在一個欄位，而是 constructor／方法 parameter 來源中剛好有
   一個不同的 `*UseCase` 型別。

## 已知限制與例外

參數存在不證明真的呼叫 UseCase，也不證明恰好執行一次；不分析方法呼叫順序、欄位注入或 DI。可有其他不在禁止清單的參數。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1017.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1017`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
