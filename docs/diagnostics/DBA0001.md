# DBA0001：無效的 Analyzer 設定

## 目的與預設嚴重性

設定錯誤會使本次規則評估無效；不能將因設定錯誤而沒有其他診斷當成通過。預設為不可停用的 Error。

## 設計理由與取捨

本項是 ArchPrecept 的[設定與證據契約](../product/rule-design-rationale.md#evidence)，不虛構 DDD／Clean Architecture 出處。規則及角色必須能從本次編譯輸入明確重現；無效或歧義設定若悄悄落入預設，沒有診斷就可能被誤讀為合規。

代價是設定錯誤必須先修正才能形成有效評估。此規則只能看編譯器收到的 AdditionalFiles；設定檔留在磁碟、Analyzer 沒有載入或其執行失敗，都需要另外核對，不能由 DBA0001 的缺席推斷正常。

## 適用範圍與觸發條件

AdditionalFiles 的 repository／project 設定重複、不能讀取、違反 Schema、含未知欄位／Profile／角色／Diagnostic、無效 severity，或明確 mapping 無法唯一解析時回報。外部 XML entity／DTD 禁止使用。

共同設定、權威與角色優先序見 [Analyzer 採用政策](../product/analyzer-policy.md)。

## 違規範例

```xml
<ArchPrecept version="1" profiles="typo" />
```

## 合規範例

```xml
<ArchPrecept version="1" profiles="core" namingConventions="false" />
```

## 修正指引

依訊息修正檔名、Schema 欄位或完整 metadata／assembly mapping。若使用自有契約，組件必須存在於本次 compilation，泛型 metadata 名稱必須含 arity。

## 已知限制與例外

本規則只能看到明確傳入 AdditionalFiles 的設定；忘記加入檔案時仍採目前預設，不能憑檔案存在於磁碟就聲稱設定已生效。未知 dependency／載入錯誤也不能靠此診斷保證被捕捉。

## 設定與 Suppression

DBA0001 的 NotConfigurable metadata 避免設定錯誤被一般 severity 掩蓋。請修正設定，不以 suppression 作為有效採用結果。

## 對應實作與測試

- 實作：ConfigurationCoverageAnalyzer.cs、AnalyzerConfiguration.cs、RoleClassifier.cs（src/Analyzers/ArchPrecept.Analyzers.Core）。
- 語意測試：ConfigurationCoverageAnalyzerTests。
- 實際套件：SDK 8／10 的 [consumer 入口](../../eng/Test-PackageConsumer.ps1)。
- Descriptor／文件連結由 DiagnosticDocumentationCoverageTests 核對；產品規則另由 [唯一 Catalog](../../rules/catalog.xml) 連接來源、實作與測試。
