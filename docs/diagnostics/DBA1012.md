# DBA1012：Use Case 不應直接建立 Repository

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1012</code>
- **標題**：Use case should not construct repositories
- **預設 severity**：<code>Error</code>（預設啟用）

Use Case 與 Handler 應依賴 Repository Port，而非直接決定具體持久化實作。具體 Repository 的建立與組態屬於 composition root 的責任。

## 適用範圍與觸發條件

### 適用範圍

規則分析 C# 的 <code>new</code> 物件建立運算式。若包含該運算式的型別名稱以區分大小寫的 <code>UseCase</code> 或 <code>Handler</code> 結尾，即進入檢查；產生程式碼不在範圍內。

### 精確觸發條件

同時符合下列條件時，會在 <code>new</code> 後方的型別語法位置回報 <code>DBA1012</code>：

1. <code>new</code> 建立目標的語意型別名稱以 <code>Repository</code> 結尾；
2. 目前包含該運算式的型別名稱以 <code>UseCase</code> 或 <code>Handler</code> 結尾。

規則不會判斷建立的型別是否真的連到資料庫；名稱後綴是唯一的 Repository 辨識方式。

## 違規範例

~~~csharp
public sealed class SqlOrderRepository
{
}

public sealed class PlaceOrderHandler
{
    public object Handle() => new SqlOrderRepository(); // DBA1012
}
~~~

## 合規範例

~~~csharp
public interface IOrderRepository
{
}

public sealed class SqlOrderRepository : IOrderRepository
{
}

public sealed class PlaceOrderUseCase
{
    private readonly IOrderRepository repository;

    public PlaceOrderUseCase(IOrderRepository repository)
    {
        this.repository = repository;
    }
}

public static class CompositionRoot
{
    public static PlaceOrderUseCase Create()
        => new(new SqlOrderRepository());
}
~~~

<code>SqlOrderRepository</code> 的建立發生在不以 <code>UseCase</code> 或 <code>Handler</code> 結尾的 composition root，因此不會觸發此規則。

## 修正指引

1. 為 Use Case 或 Handler 所需的持久化行為定義或使用 Repository Port。
2. 以建構子注入該 Port，讓型別可明確宣告所需的相依。
3. 把具體 Repository 的 <code>new</code>、DI 註冊與連線設定移至 composition root。
4. 若 Handler 是 Command 或 Query dispatch Handler，也一併確認其相依符合 <code>DBA1017</code> 的邊界。

## 已知限制與例外

- 規則只比較建立型別與包含型別的名稱後綴；同名但非持久化的 <code>*Repository</code> 型別仍可能被回報。
- 未以 <code>new</code> 直接建立的情形，例如工廠、反射或 Service Locator，不會由此規則偵測。
- 不以 <code>UseCase</code> 或 <code>Handler</code> 結尾的型別，即使直接建立 Repository，也不在此規則範圍內。
- 規則不檢查 Repository 是不是介面、抽象類別或 DI 註冊，也不驗證 composition root 的正確性。

## 設定與 Suppression

目前沒有 <code>DBA1012</code> 專屬設定。可用 <code>.editorconfig</code> 變更 severity：

~~~ini
[*.cs]
dotnet_diagnostic.DBA1012.severity = warning
~~~

若在受控遷移期間必須保留直接建立，suppression 應緊貼違規程式碼並指向移除工作：

~~~csharp
#pragma warning disable DBA1012 // 遷移中的舊組合邏輯；替代方案：...
var repository = new SqlOrderRepository();
#pragma warning restore DBA1012
~~~

也可以專案範圍停用，但這會影響所有 Use Case 與 Handler：

~~~xml
<PropertyGroup>
  <NoWarn>$(NoWarn);DBA1012</NoWarn>
</PropertyGroup>
~~~
