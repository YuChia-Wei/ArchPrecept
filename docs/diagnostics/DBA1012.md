# DBA1012：Use Case 不應直接建立 Repository

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1012</code>
- **標題**：Use case should not construct repositories
- **預設 severity**：<code>Error</code>（預設啟用）

Use Case 與 Handler 應依賴 Repository Port，而非直接決定具體持久化實作。具體 Repository 的建立與組態屬於 composition root 的責任。

## 設計理由與取捨

[Dependency Rule 及 Port／Adapter 分工](../product/rule-design-rationale.md#application)支持 Application 表達所需能力、由外部組裝具體實作。產品禁止 Use Case／Handler 自行建立 Repository，避免把 Provider、連線與生命週期決策寫進應用流程。

代價是需要明確 Port 與組裝設定，以換取測試及儲存 Adapter 的可替換性。限制不禁止建立領域物件或 Input；現版只檢查明示物件建立，未涵蓋 Factory、反射或間接建立。

## 適用範圍與觸發條件

檢查已辨識為 use-case 或 handler 的 class／record／struct 中明示 `new T(...)` 或 target-typed `new(...)`；T 辨識為 repository 時回報。只針對物件建立語法，不分析 DI 註冊或執行期解析。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。目前未設定時採 `legacy`，以下名稱式範例以此預設為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

~~~csharp
public sealed class SqlOrderRepository
{
}

public sealed class PlaceOrderHandler
{
    public object Handle() => new SqlOrderRepository(); // DBA1012
}
~~~

## 合規範例

~~~csharp
public interface IOrderRepository
{
}

public sealed class SqlOrderRepository : IOrderRepository
{
}

public sealed class PlaceOrderUseCase
{
    private readonly IOrderRepository repository;

    public PlaceOrderUseCase(IOrderRepository repository)
    {
        this.repository = repository;
    }
}

public static class CompositionRoot
{
    public static PlaceOrderUseCase Create()
        => new(new SqlOrderRepository());
}
~~~

<code>SqlOrderRepository</code> 的建立發生在不以 <code>UseCase</code> 或 <code>Handler</code> 結尾的 composition root，因此不會觸發此規則。

## 修正指引

1. 為 Use Case 或 Handler 所需的持久化行為定義或使用 Repository Port。
2. 以建構子注入該 Port，讓型別可明確宣告所需的相依。
3. 把具體 Repository 的 <code>new</code>、DI 註冊與連線設定移至 composition root。
4. 若 Handler 是 Command 或 Query dispatch Handler，也一併確認其相依符合 <code>DBA1017</code> 的邊界。

## 已知限制與例外

不分析 factory、反射或隱藏在其他方法中的建立流程；一般 class 若未被辨識為相關角色，不會無聲宣稱已完成此檢查。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1012.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1012`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
