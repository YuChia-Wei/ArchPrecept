# DBA1011：Handler 不應混合 Command 與 Query 職責

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1011</code>
- **標題**：Handler should not mix command and query responsibilities
- **預設 severity**：<code>Error</code>（預設啟用）

CQRS 的 Command 與 Query 有不同的副作用與讀取責任。單一 Handler 同時處理兩者會模糊邊界，讓依賴、測試與擴充策略難以維持一致。

## 適用範圍與觸發條件

### 適用範圍

規則分析名稱以區分大小寫的 <code>UseCase</code> 或 <code>Handler</code> 結尾的 C# 類別；產生程式碼不在分析範圍內。

### 精確觸發條件

Analyzer 檢查型別自行宣告的成員方法。若同一適用型別中同時存在下列兩種情況，會在型別宣告位置回報一次 <code>DBA1011</code>：

1. 至少一個名為 <code>Handle</code> 或 <code>HandleAsync</code>、且至少有一個參數的方法，其第一個參數型別是名稱為 <code>ICommand</code> 的介面，或實作了名稱為 <code>ICommand</code> 的介面。
2. 至少一個同樣形狀的方法，其第一個參數型別是名稱為 <code>IQuery</code> 的介面，或實作了名稱為 <code>IQuery</code> 的介面。

兩種 marker 可以出現在不同方法，或出現在同一個第一參數型別的介面集合中。

## 違規範例

~~~csharp
public interface ICommand<T>
{
}

public interface IQuery<T>
{
}

public sealed class CreateOrder : ICommand<string>
{
}

public sealed class GetOrder : IQuery<string>
{
}

public sealed class OrderHandler
{
    public string Handle(CreateOrder command) => string.Empty;

    public string Handle(GetOrder query) => string.Empty;
}
~~~

<code>OrderHandler</code> 同時處理 Command 與 Query marker，因此會回報 <code>DBA1011</code>。

## 合規範例

~~~csharp
public sealed class CreateOrderHandler
{
    public string Handle(CreateOrder command) => string.Empty;
}

public sealed class GetOrderHandler
{
    public string Handle(GetOrder query) => string.Empty;
}
~~~

## 修正指引

1. 將 Command 與 Query 的處理拆分為不同的 Handler。
2. 讓每個 Handler 的 <code>Handle</code> 或 <code>HandleAsync</code> 入口只接受單一角色的訊息。
3. 將共用的無狀態轉換或查詢邏輯抽出，但不要讓共用元件重新成為同時協調讀寫的 Handler。
4. 若 API 端點需要同時回應資料與執行命令，請由端點或明確的 Use Case 編排，而非由同一個 dispatch Handler 吸收兩種 marker。

## 已知限制與例外

- Marker 辨識只比較介面簡單名稱 <code>ICommand</code> 與 <code>IQuery</code>；命名空間與泛型型別引數不參與判斷。
- 只檢查名稱精確為 <code>Handle</code> 或 <code>HandleAsync</code> 的成員，且只看第一個參數；其他入口命名或後續參數不會觸發此規則。
- Analyzer 只巡覽型別自行宣告的成員，繼承而來的 Handler 方法不在這個檢查中。
- 名稱類似 <code>ICommandBus</code> 或 <code>IQueryBus</code> 的型別並不等於 marker，且不會因此觸發。
- 這是角色分離規則，未驗證 Command 是否真的寫入、Query 是否真的唯讀。

## 設定與 Suppression

目前沒有 <code>DBA1011</code> 專屬設定。可在 <code>.editorconfig</code> 調整 severity：

~~~ini
[*.cs]
dotnet_diagnostic.DBA1011.severity = warning
~~~

若因既有整合暫時必須保留混合 Handler，應只對該型別施加局部 suppression，並記錄拆分期限：

~~~csharp
#pragma warning disable DBA1011 // 相容性 Handler；拆分工作項目：...
public sealed class LegacyOrderHandler
{
}
#pragma warning restore DBA1011
~~~

專案層級停用的做法如下，但不應取代角色拆分：

~~~xml
<PropertyGroup>
  <NoWarn>$(NoWarn);DBA1011</NoWarn>
</PropertyGroup>
~~~
