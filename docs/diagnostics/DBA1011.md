# DBA1011：Handler 不應混合 Command 與 Query 職責

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1011</code>
- **標題**：Handler should not mix command and query responsibilities
- **預設 severity**：<code>Error</code>（預設啟用）

CQRS 的 Command 與 Query 有不同的副作用與讀取責任。單一 Handler 同時處理兩者會模糊邊界，讓依賴、測試與擴充策略難以維持一致。

## 適用範圍與觸發條件

檢查已辨識為 handler／use-case 的 class／record／struct 之直接 `Handle`／`HandleAsync` 方法。第一個參數分別辨識為 command 與 query 時，表示同一型別混合兩種責任，回報一次。Command／Query 的明確 mapping、繼承與選用名稱慣例共用中央分類器。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。未設定時採 legacy，以下名稱式範例以此相容模式為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

~~~csharp
public interface ICommand<T>
{
}

public interface IQuery<T>
{
}

public sealed class CreateOrder : ICommand<string>
{
}

public sealed class GetOrder : IQuery<string>
{
}

public sealed class OrderHandler
{
    public string Handle(CreateOrder command) => string.Empty;

    public string Handle(GetOrder query) => string.Empty;
}
~~~

<code>OrderHandler</code> 同時處理 Command 與 Query marker，因此會回報 <code>DBA1011</code>。

## 合規範例

~~~csharp
public sealed class CreateOrderHandler
{
    public string Handle(CreateOrder command) => string.Empty;
}

public sealed class GetOrderHandler
{
    public string Handle(GetOrder query) => string.Empty;
}
~~~

## 修正指引

1. 將 Command 與 Query 的處理拆分為不同的 Handler。
2. 讓每個 Handler 的 <code>Handle</code> 或 <code>HandleAsync</code> 入口只接受單一角色的訊息。
3. 將共用的無狀態轉換或查詢邏輯抽出，但不要讓共用元件重新成為同時協調讀寫的 Handler。
4. 若 API 端點需要同時回應資料與執行命令，請由端點或明確的 Use Case 編排，而非由同一個 dispatch Handler 吸收兩種 marker。

## 已知限制與例外

只看 Handle／HandleAsync 第一參數的靜態型別，不推論 runtime 路由、方法呼叫或訊息處理次數。只選 messaging Profile 不會自動要求 framework 的薄 Handler 慣例。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1011.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1011`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
