# DBA1006：Controller 不應直接建立 Handler 或 Use Case

## 目的與預設嚴重性

此規則禁止 Controller 直接 `new` 出 Handler 或 Use Case，要求由 composition root 進行相依組合，並讓 Controller 透過明確的 Use Case 介面委派行為。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1006` |
| Descriptor 標題 | `Controller should not construct handlers or use cases` |
| 類別 | `Architecture` |
| 預設嚴重性 | `error` |
| 預設啟用 | 是 |

## 適用範圍與觸發條件

分析器只分析 C# 來源中非抽象、名稱以大小寫相符 `Controller` 結尾的 class，且不分析產生的程式碼。

在該 class 的所有後代節點中，每一個 `new` 物件建立運算式都會取得建立型別的語意名稱；若無法取得語意型別，改用原始型別語法文字。只要該名稱以 `Handler` 或 `UseCase` 結尾，就在 `new` 的型別位置回報 `DBA1006`。

此規則只處理直接建構。將 Handler 作為建構式相依注入是另一條規則（`DBA1014`）的範圍，並不會由 `DBA1006` 回報。

## 違規範例

```csharp
using Microsoft.AspNetCore.Mvc;

public sealed class CreateResourceHandler { }

[ApiController]
public sealed class ResourceController : ControllerBase
{
    public object Execute()
    {
        return new CreateResourceHandler();
    }
}
```

`new CreateResourceHandler()` 直接觸發 `DBA1006`。

## 合規範例

```csharp
using Microsoft.AspNetCore.Mvc;

public interface ICreateResourceUseCase
{
    void Execute();
}

[ApiController]
public sealed class ResourceController : ControllerBase
{
    private readonly ICreateResourceUseCase useCase;

    public ResourceController(ICreateResourceUseCase useCase)
    {
        this.useCase = useCase;
    }

    public void Execute()
    {
        useCase.Execute();
    }
}
```

Use Case 實作與其相依應在 composition root 註冊與組合；Controller 只持有明確抽象。

## 修正指引

1. 刪除 Controller 中 `new SomeHandler(...)` 或 `new SomeUseCase(...)` 的組合邏輯。
2. 定義並注入對應的 Use Case 介面，讓 Controller 只呼叫 Application 行為。
3. 在 composition root 註冊 Use Case 實作及其 Infrastructure 相依，讓容器處理生命週期與組合。
4. 若目前架構以 Handler 作為入口，先將 Handler 調整為適配一個 Use Case，再由 Controller 依產品採用模型注入 Use Case 抽象。

## 已知限制與例外

- 角色判定僅看建立型別名稱的後綴，不檢查 namespace、介面實作或實際職責。因此名稱以 `Handler`／`UseCase` 結尾但非 Application 邊界的類別也可能觸發；反之，改名的等價類別不會觸發。
- 規則只偵測直接 `new`。Factory、反射、Service Locator、容器解析或由其他方法回傳的 Handler／Use Case 不在此規則的偵測範圍。
- Controller 的辨識同樣只依 class 名稱後綴；抽象 Controller 完全略過。規則不提供 code fix、白名單或規則專屬例外設定。
- 若真正的問題是注入具體 Handler、Message Bus、Dispatcher、寫入 Repository 或 Domain Service，請處理 `DBA1014`，不要以本規則的 suppression 取代責任切分。

## 設定與 Suppression

目前沒有規則專屬設定鍵。預設採用端範本為：

```editorconfig
[*.cs]
dotnet_diagnostic.DBA1006.severity = error
```

若存在已核准且有期限的外部整合例外，可用最小範圍 pragma：

```csharp
#pragma warning disable DBA1006 // 外部整合過渡；追蹤項目：<id>
var legacy = new LegacyHandler();
#pragma warning restore DBA1006
```

可用值為 `none`、`silent`、`suggestion`、`warning`、`error`。對一般 API Controller，優先保留 `error` 並修正 composition root，而不是全域停用。
