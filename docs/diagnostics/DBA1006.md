# DBA1006：Controller 不應直接建立 Handler 或 Use Case

## 目的與預設嚴重性

此規則禁止 Controller 直接 `new` 出 Handler 或 Use Case，要求由 composition root 進行相依組合，並讓 Controller 透過明確的 Use Case 介面委派行為。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1006` |
| Descriptor 標題 | `Controller should not construct handlers or use cases` |
| 類別 | `Architecture` |
| 預設嚴重性 | `error` |
| 預設啟用 | 是 |

## 設計理由與取捨

[Ports and Adapters 與 DIP](../product/rule-design-rationale.md#application)支持把入口轉接和具體服務組裝分開。產品要求 Controller 接收已組裝的 Use Case Port，避免 Controller 自行選擇 Handler／Use Case 的具體實作、生命週期及協作者。

代價是新增明確契約與 Composition Root 接線。規則只限制指定應用角色，不禁止建立 Input、DTO 或一般值；本候選涵蓋明示 `new T` 及 target-typed `new()`，仍未涵蓋所有 Factory 或反射。

## 適用範圍與觸發條件

檢查已辨識為 controller 的非抽象 class／record。其 `new T(...)` 或 target-typed `new(...)` 型別辨識為 handler 或 use-case 時回報；角色來自中央分類器，而非各規則自行判斷尾碼。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。目前未設定時採 `legacy`，以下名稱式範例以此預設為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

```csharp
using Microsoft.AspNetCore.Mvc;

public sealed class CreateResourceHandler { }

[ApiController]
public sealed class ResourceController : ControllerBase
{
    public object Execute()
    {
        return new CreateResourceHandler();
    }
}
```

`new CreateResourceHandler()` 直接觸發 `DBA1006`。

## 合規範例

```csharp
using Microsoft.AspNetCore.Mvc;

public interface ICreateResourceUseCase
{
    void Execute();
}

[ApiController]
public sealed class ResourceController : ControllerBase
{
    private readonly ICreateResourceUseCase useCase;

    public ResourceController(ICreateResourceUseCase useCase)
    {
        this.useCase = useCase;
    }

    public void Execute()
    {
        useCase.Execute();
    }
}
```

Use Case 實作與其相依應在 composition root 註冊與組合；Controller 只持有明確抽象。

## 修正指引

1. 刪除 Controller 中 `new SomeHandler(...)` 或 `new SomeUseCase(...)` 的組合邏輯。
2. 定義並注入對應的 Use Case 介面，讓 Controller 只呼叫 Application 行為。
3. 在 composition root 註冊 Use Case 實作及其 Infrastructure 相依，讓容器處理生命週期與組合。
4. 若目前架構以 Handler 作為入口，先將 Handler 調整為適配一個 Use Case，再由 Controller 依產品採用模型注入 Use Case 抽象。

## 已知限制與例外

檢查明示與 target-typed object creation，不分析 factory、反射或 DI resolve；Controller 中所有呼叫是否正確協調仍需行為測試。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1006.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1006`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
