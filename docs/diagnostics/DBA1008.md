# DBA1008：Mapper 不應相依應用或持久化服務

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1008</code>
- **標題**：Mapper should not depend on application or persistence services
- **預設 severity**：<code>Warning</code>（預設啟用）

Mapper 應只進行物件或資料形狀的轉換。Repository、Use Case 與 Handler 相依會讓轉換器取得應用流程或持久化責任，降低可預測性與可重用性。

## 適用範圍與觸發條件

檢查已辨識為 mapper 的 class／record／struct 中的型別語法。其型別辨識為 repository、use-case 或 handler 時回報。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。未設定時採 legacy，以下名稱式範例以此相容模式為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

~~~csharp
public sealed record Order(string Id);
public sealed record OrderDto(string Id);

public interface IOrderRepository
{
    Order Find(string id);
}

public static class OrderMapper
{
    public static OrderDto ToDto(Order order, IOrderRepository repository)
        => new(order.Id);
}
~~~

參數型別 <code>IOrderRepository</code> 以 <code>Repository</code> 結尾，因此會回報 <code>DBA1008</code>。

## 合規範例

~~~csharp
public static class OrderMapper
{
    public static OrderDto ToDto(Order order)
        => new(order.Id);
}
~~~

呼叫端應先完成查詢或協調，再把 Mapper 所需的資料傳入。

## 修正指引

1. 在 Use Case、Handler 或其他應用服務中取得資料並做流程協調。
2. 將 Mapper 縮小為只接受來源物件、值物件或明確的轉換資料。
3. 移除 Mapper 的 Repository、Use Case 或 Handler 型別欄位、屬性、方法參數、回傳型別與泛型型別引數。
4. 同時確認類別符合 <code>DBA1007</code> 的 <code>static</code> 要求。

## 已知限制與例外

型別語法檢查不證明實際執行路徑，也不涵蓋 dynamic／反射與完整跨專案依賴。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1008.severity = warning
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1008`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
