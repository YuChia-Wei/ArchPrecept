# DBA1003：Aggregate 不應相依基礎設施型別

## 目的與預設嚴重性

此規則避免 Aggregate 或 Entity 直接引用 `DbContext` 型別，讓 Domain 模型維持與持久化基礎設施分離。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1003` |
| Descriptor 標題 | `Aggregate should not depend on infrastructure types` |
| 類別 | `Architecture` |
| 預設嚴重性 | `warning` |
| 預設啟用 | 是 |

## 適用範圍與觸發條件

檢查已辨識為 aggregate 或 entity 的 class／record／struct／record struct 宣告中的型別語法。被參考型別若辨識為 db-context，則在該次參考位置回報。內建 EF Core DbContext、明確自有 mapping 與選用的 DbContext 命名慣例都由中央分類器處理。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。未設定時採 legacy，以下名稱式範例以此相容模式為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

```csharp
using Microsoft.EntityFrameworkCore;

public sealed class OrderAggregate
{
    private readonly DbContext dbContext;

    public OrderAggregate(DbContext dbContext)
    {
        this.dbContext = dbContext;
    }
}
```

欄位與建構式參數都是候選 class 內的型別使用；各出現位置都可能產生 `DBA1003`。

## 合規範例

```csharp
public sealed class OrderAggregate
{
    public OrderAggregate(string id)
    {
        Id = id;
    }

    public string Id { get; }
}

// DbContext 應位於 Repository 或其他 Infrastructure 實作中，
// 而不是 Aggregate 內。
```

## 修正指引

1. 從 Aggregate／Entity 的欄位、屬性、建構式與方法簽章移除 `DbContext` 與其衍生型別。
2. 將查詢、追蹤、交易與持久化工作移至 Infrastructure Repository、Unit of Work 或 Application Use Case。
3. Aggregate 只接收值、值物件與領域抽象所需資料；需要外部資料時，先在 Application 層取得並以明確輸入傳入。
4. 若因框架模型需要保留基礎設施型別，先確認此 class 是否真的是 Domain Aggregate；不要只靠 suppression 掩蓋責任混合。

## 已知限制與例外

掃描型別語法而非跨 Project 相依圖；巢狀宣告仍可能出現在外層的後代語法中。此規則不是所有 Infrastructure API 的完整清單；其他資料庫、I/O 或 runtime 服務需另訂 mapping／規則。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1003.severity = warning
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1003`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
