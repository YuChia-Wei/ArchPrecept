# DBA1007：Mapper 應為 static 類別

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1007</code>
- **標題**：Mapper should be static
- **預設 severity**：<code>Warning</code>（預設啟用）

此規則將 Mapper 視為決定性、無執行個體狀態的轉換器。以 <code>static</code> 類別表達此限制，可避免 Mapper 形成建構子注入圖或保存執行個體狀態。

## 適用範圍與觸發條件

檢查已辨識為 mapper 的 class／record／struct；非 `static` 時回報。這是 `framework` Profile 選定的靜態 Mapper 慣例，不是所有 CA／HexArch 專案的通用必要條件。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。未設定時採 legacy，以下名稱式範例以此相容模式為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

~~~csharp
public sealed record Order(string Id);
public sealed record OrderDto(string Id);

public sealed class OrderMapper
{
    public OrderDto ToDto(Order order) => new(order.Id);
}
~~~

<code>OrderMapper</code> 名稱符合 Mapper 辨識條件，但類別不是 <code>static</code>，因此會回報 <code>DBA1007</code>。

## 合規範例

~~~csharp
public sealed record Order(string Id);
public sealed record OrderDto(string Id);

public static class OrderMapper
{
    public static OrderDto ToDto(Order order) => new(order.Id);
}
~~~

## 修正指引

1. 若型別確實只負責資料轉換，將類別及其操作改為 <code>static</code>。
2. 將需要查詢 Repository、呼叫 Use Case 或保存狀態的工作移至呼叫端或應用服務；Mapper 只接收已備妥的輸入資料。
3. 若型別不是 Mapper，請改用能正確表達角色的名稱，而非以 <code>Mapper</code> 結尾。

## 已知限制與例外

不證明 Mapper 是純函式、deterministic 或沒有靜態可變狀態。需要 instance mapper 的團隊可不選本慣例或停用此規則。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1007.severity = warning
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1007`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
