# DBA1007：Mapper 應為 static 類別

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1007</code>
- **標題**：Mapper should be static
- **預設 severity**：<code>Warning</code>（預設啟用）

此規則將 Mapper 視為決定性、無執行個體狀態的轉換器。以 <code>static</code> 類別表達此限制，可避免 Mapper 形成建構子注入圖或保存執行個體狀態。

## 適用範圍與觸發條件

### 適用範圍

規則只分析 C# 的類別宣告，且類別名稱必須以區分大小寫的 <code>Mapper</code> 結尾。Analyzer 已設定不分析產生的程式碼。

### 精確觸發條件

同時符合下列條件時，會在類別識別字位置回報一次 <code>DBA1007</code>：

1. 宣告為 <code>class</code>；
2. 類別名稱以 <code>Mapper</code> 結尾；
3. 該類別不是 <code>static</code>。

## 違規範例

~~~csharp
public sealed record Order(string Id);
public sealed record OrderDto(string Id);

public sealed class OrderMapper
{
    public OrderDto ToDto(Order order) => new(order.Id);
}
~~~

<code>OrderMapper</code> 名稱符合 Mapper 辨識條件，但類別不是 <code>static</code>，因此會回報 <code>DBA1007</code>。

## 合規範例

~~~csharp
public sealed record Order(string Id);
public sealed record OrderDto(string Id);

public static class OrderMapper
{
    public static OrderDto ToDto(Order order) => new(order.Id);
}
~~~

## 修正指引

1. 若型別確實只負責資料轉換，將類別及其操作改為 <code>static</code>。
2. 將需要查詢 Repository、呼叫 Use Case 或保存狀態的工作移至呼叫端或應用服務；Mapper 只接收已備妥的輸入資料。
3. 若型別不是 Mapper，請改用能正確表達角色的名稱，而非以 <code>Mapper</code> 結尾。

## 已知限制與例外

- 辨識完全依賴類別名稱後綴；名稱不以 <code>Mapper</code> 結尾的轉換器不在此規則範圍內。
- 規則只檢查類別是否為 <code>static</code>，不會判斷實際轉換邏輯是否為純函式。
- <code>record</code>、<code>struct</code>、介面與產生程式碼不會由此規則分析。
- 若專案刻意採用具狀態或可替換的 Mapper 實作，應先確認該設計的架構理由，再以最小範圍抑制此診斷。

## 設定與 Suppression

目前 Analyzer 未提供 <code>DBA1007</code> 專屬的 AnalyzerConfig 選項；可用標準 Roslyn severity 設定調整強度：

~~~ini
# .editorconfig
[*.cs]
dotnet_diagnostic.DBA1007.severity = error
~~~

若例外只限單一區塊，使用局部 <code>pragma</code>，並在註解中保留架構理由：

~~~csharp
#pragma warning disable DBA1007 // 已核准的具狀態轉換元件；追蹤項目：...
public sealed class LegacyOrderMapper
{
}
#pragma warning restore DBA1007
~~~

也可在專案檔以 <code>NoWarn</code> 停用，但其影響範圍較大，應避免用來掩蓋一般違規：

~~~xml
<PropertyGroup>
  <NoWarn>$(NoWarn);DBA1007</NoWarn>
</PropertyGroup>
~~~
