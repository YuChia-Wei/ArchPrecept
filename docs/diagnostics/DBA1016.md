# DBA1016：Use Case 相依項目被禁止

## 目的與預設嚴重性

`DBA1016` 防止 Use Case 直接依賴派送器、傳輸／框架型別或另一個 Use Case，避免
Use Case 邊界重新耦合。Roslyn Descriptor 的正式標題為
`Use Case dependency is forbidden`，分類為 `Architecture`。

| 欄位 | 值 |
|---|---|
| Diagnostic ID | `DBA1016` |
| 預設 severity | `Error`（`DiagnosticSeverity.Error`） |
| 預設啟用 | 是 |
| 產生位置 | 違規 constructor parameter 的位置 |

## 適用範圍與觸發條件

檢查已辨識為 use-case 的非抽象 class／record／struct 的 instance constructor parameters。相依為另一 use-case、transport 或 bus 時回報。真正 `ArchPrecept.Contracts.Application.IDomainEventDispatcher` 或明確映射的 domain-event-dispatcher 允許注入；其衍生契約若另混入 bus／transport／use-case，仍回報。內建豁免要求完整 metadata＋組件身分及 symbol equality；其他組件／namespace 的同名型別不會取得豁免。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。未設定時採 legacy，以下名稱式範例以此相容模式為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

```csharp
using System.Threading;
using System.Threading.Tasks;

public interface IMessageBus { }
public interface IReserveInventoryUseCase { }

public sealed class PlaceOrderUseCase
{
    // 每個禁止相依都會產生一個 DBA1016。
    public PlaceOrderUseCase(
        IMessageBus bus,
        IReserveInventoryUseCase reserveInventoryUseCase) { }

    public Task ExecuteAsync(CancellationToken cancellationToken)
        => Task.CompletedTask;
}
```

## 合規範例

```csharp
using System.Threading;
using System.Threading.Tasks;

public interface IOrderRepository { }

public sealed class PlaceOrderUseCase
{
    public PlaceOrderUseCase(IOrderRepository repository) { }

    public Task ExecuteAsync(CancellationToken cancellationToken)
        => Task.CompletedTask;
}
```

`IOrderRepository` 並不在 `DBA1016` 的禁止清單中；是否應使用該 Repository 仍須
依其他規則與架構決策判斷。

## 修正指引

1. 將 `IMessageBus`、Mediator 或 Dispatcher 的使用移至傳輸／派送 Handler；Use
   Case 應接收傳輸中立的輸入並回傳傳輸中立的結果。
2. 不要由一個 Use Case 直接注入另一個 Use Case。將共用業務行為抽取為適當的
   領域服務、Port 或由上層協調的流程。
3. 將 ASP.NET Core、Wolverine 或 MediatR 型別轉換為應用層自己的契約後再進入
   Use Case。
4. 每次移除一個禁止的建構函式參數後重新建置；本規則對每個參數獨立回報。

## 已知限制與例外

只檢查建構函式相依，不分析欄位、屬性、一般方法參數、反射或 runtime 解析。合法 domain-event port 不提供 Outbox、交易或可靠傳遞。legacy 名稱慣例仍可能誤認其他 Dispatcher；需要精確判定時停用命名並配置角色。0.0.2 使用的局部 pragma 可在升級後移除並以真實 consumer 重建驗證。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1016.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1016`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
