# DBA1016：Use Case 相依項目被禁止

## 目的與預設嚴重性

`DBA1016` 防止 Use Case 直接依賴 Vendor Bus、傳輸型別或另一個 Use Case，避免
Use Case 邊界重新耦合；Application-owned Domain Event Port 依實際契約判定。Roslyn Descriptor 的正式標題為
`Use Case dependency is forbidden`，分類為 `Architecture`。

| 欄位 | 值 |
|---|---|
| Diagnostic ID | `DBA1016` |
| 預設 severity | `Error`（`DiagnosticSeverity.Error`） |
| 預設啟用 | 是 |
| 產生位置 | 違規欄位／屬性／參數或直接呼叫位置 |

## 設計理由與取捨

[內層政策與外部機制分離](../product/rule-design-rationale.md#application)支持 Use Case 不依賴 Vendor Bus、Transport 或另一 Use Case，以避免交付技術侵入與應用流程互相串接。代價是共同行為與協調責任必須明確設計到領域服務、窄 Port 或單一應用流程。

Application-owned 的 Domain Event Dispatcher、Publisher／Outbox 能力應按真實契約評估；名稱不是禁止或豁免的充分理由。混入 Vendor Bus 的介面仍有機制耦合。本候選的精確 port 豁免與宣告／直接呼叫檢查不提供 Outbox 原子性、可靠交付或完整相依圖證明。

## 適用範圍與觸發條件

檢查已辨識為 use-case 的 class／record／struct 直接欄位、屬性、constructor／一般方法參數及方法體直接 invocation（包含 abstract 型別中的實際宣告）。相依為另一 use-case、transport 或 bus 時回報。真正 `ArchPrecept.Contracts.Application.IDomainEventDispatcher`、`ArchPrecept.Contracts.Application.Messaging.IIntegrationEventPublisher`，或明確映射的 domain-event-dispatcher／integration-event-publisher／outbox-port 允許注入；其衍生契約若另混入 bus／transport／use-case，仍回報。內建豁免要求完整 metadata＋組件身分及 symbol equality；其他組件／namespace 的同名型別不會取得豁免。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。目前未設定時採 `legacy`，以下名稱式範例以此預設為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

```csharp
using System.Threading;
using System.Threading.Tasks;

public interface IMessageBus { }
public interface IReserveInventoryUseCase { }

public sealed class PlaceOrderUseCase
{
    // 每個禁止相依都會產生一個 DBA1016。
    public PlaceOrderUseCase(
        IMessageBus bus,
        IReserveInventoryUseCase reserveInventoryUseCase) { }

    public Task ExecuteAsync(CancellationToken cancellationToken)
        => Task.CompletedTask;
}
```

## 合規範例

```csharp
using System.Threading;
using System.Threading.Tasks;

public interface IOrderRepository { }

public sealed class PlaceOrderUseCase
{
    public PlaceOrderUseCase(IOrderRepository repository) { }

    public Task ExecuteAsync(CancellationToken cancellationToken)
        => Task.CompletedTask;
}
```

`IOrderRepository` 並不在 `DBA1016` 的禁止清單中；是否應使用該 Repository 仍須
依其他規則與架構決策判斷。

## 修正指引

1. 將 Vendor Bus、Mediator 或傳輸派送器的使用留在外部 Adapter；Use Case 接收並回傳傳輸中立的資料。應用若需要發布能力，使用 Application-owned 的窄 Port，不能把 Vendor API 換名後直接帶入。
2. 不要由一個 Use Case 直接注入另一個 Use Case。將共用業務行為抽取為適當的
   領域服務、Port 或由上層協調的流程。
3. 將 ASP.NET Core、Wolverine 或 MediatR 型別轉換為應用層自己的契約後再進入
   Use Case。
4. 每次移除一個禁止的建構函式參數後重新建置；本規則對每個參數獨立回報。

## 已知限制與例外

不追蹤繼承而未重新宣告的外部 metadata 成員、generic wrapper 內部依賴、反射、動態解析或任意跨方法資料流。合法 domain-event／publisher／outbox port 不提供交易或可靠傳遞。legacy 名稱慣例仍可能誤認其他 Dispatcher；需要精確判定時停用命名並配置角色。合法 port 不豁免混入的 forbidden capability，型別與實際呼叫可各自回報；本規則不驗證 Outbox 實作責任。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1016.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1016`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
