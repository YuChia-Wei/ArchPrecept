# DBA1016：Use Case 相依項目被禁止

## 目的與預設嚴重性

`DBA1016` 防止 Use Case 直接依賴派送器、傳輸／框架型別或另一個 Use Case，避免
Use Case 邊界重新耦合。Roslyn Descriptor 的正式標題為
`Use Case dependency is forbidden`，分類為 `Architecture`。

| 欄位 | 值 |
|---|---|
| Diagnostic ID | `DBA1016` |
| 預設 severity | `Error`（`DiagnosticSeverity.Error`） |
| 預設啟用 | 是 |
| 產生位置 | 違規 constructor parameter 的位置 |

## 適用範圍與觸發條件

此規則由 `UseCaseServiceProviderInjectionAnalyzer` 執行，且會略過產生的程式碼。它
只檢查名稱以區分大小寫的 `UseCase` 結尾、且不是 `abstract` 的 C# 類別之 instance
constructor parameter；同名介面、欄位、屬性與一般方法參數不在 `DBA1016` 的檢查
範圍內。

任一建構函式參數的型別符合下列條件時，該參數會產生一個 `DBA1016`：

| 判定 | 精確條件 |
|---|---|
| Bus／Mediator／Dispatcher | 簡單名稱正好是 `IMessageBus`、`IMediator` 或 `IDispatcher`，或以 `Dispatcher` 結尾 |
| 另一個 Use Case | 簡單名稱以 `UseCase` 結尾 |
| 框架／傳輸相依 | 型別所屬命名空間以 `Wolverine`、`MediatR` 或 `Microsoft.AspNetCore` 開頭 |

每個違規參數都會各自回報，因此一個建構函式同時注入 Bus 與另一個 Use Case 時會
得到兩個 `DBA1016`。

## 違規範例

```csharp
using System.Threading;
using System.Threading.Tasks;

public interface IMessageBus { }
public interface IReserveInventoryUseCase { }

public sealed class PlaceOrderUseCase
{
    // 每個禁止相依都會產生一個 DBA1016。
    public PlaceOrderUseCase(
        IMessageBus bus,
        IReserveInventoryUseCase reserveInventoryUseCase) { }

    public Task ExecuteAsync(CancellationToken cancellationToken)
        => Task.CompletedTask;
}
```

## 合規範例

```csharp
using System.Threading;
using System.Threading.Tasks;

public interface IOrderRepository { }

public sealed class PlaceOrderUseCase
{
    public PlaceOrderUseCase(IOrderRepository repository) { }

    public Task ExecuteAsync(CancellationToken cancellationToken)
        => Task.CompletedTask;
}
```

`IOrderRepository` 並不在 `DBA1016` 的禁止清單中；是否應使用該 Repository 仍須
依其他規則與架構決策判斷。

## 修正指引

1. 將 `IMessageBus`、Mediator 或 Dispatcher 的使用移至傳輸／派送 Handler；Use
   Case 應接收傳輸中立的輸入並回傳傳輸中立的結果。
2. 不要由一個 Use Case 直接注入另一個 Use Case。將共用業務行為抽取為適當的
   領域服務、Port 或由上層協調的流程。
3. 將 ASP.NET Core、Wolverine 或 MediatR 型別轉換為應用層自己的契約後再進入
   Use Case。
4. 每次移除一個禁止的建構函式參數後重新建置；本規則對每個參數獨立回報。

## 已知限制與例外

- 判定使用型別簡單名稱及命名空間字串前綴，而不是組件身分或語意角色；同名型別
  可能誤報，重新命名不等於完成架構修正。
- 目前程式碼不會因 constructor parameter 名稱以 `Request`、`Command`、`Query`
  等結尾就回報 `DBA1016`；這些名稱式輸入限制屬於 `DBA1015`。
- 規則不檢查欄位、屬性、一般方法參數、靜態呼叫或執行期服務解析；它們可能受
  其他診斷約束，也可能尚未被這個診斷涵蓋。
- `abstract` 的 `*UseCase` 類別與名稱不以 `UseCase` 結尾的類別不會進入此檢查。
- Repository 並非本規則的禁止型別；在 Use Case／Handler 內直接 `new` Repository
  則是 `DBA1012` 的範圍。

## 設定與 Suppression

目前實作沒有讀取自訂設定。使用標準 Roslyn 診斷設定可變更嚴重性或停用規則：

```ini
[*.cs]
dotnet_diagnostic.DBA1016.severity = none
```

若相容層必須暫時保留違規相依，僅在最小範圍 suppression，並記錄撤除計畫：

```csharp
#pragma warning disable DBA1016 // 舊版訊息轉接器，移轉完成後移除。
public PlaceOrderUseCase(IMessageBus bus) { }
#pragma warning restore DBA1016
```

## 對應實作與測試

- 實作：`src/Analyzers/EngineeringGuardrails.Analyzers.Core/UseCaseServiceProviderInjectionAnalyzer.cs`
  的 `AnalyzeUseCaseImplementation` 與 `IsForbiddenUseCaseDependency`。
- Descriptor：`src/Analyzers/EngineeringGuardrails.Analyzers.Core/RuleDescriptors.cs`
  的 `UseCaseForbiddenDependency`。
- 現有違規測試：
  `UseCaseServiceProviderInjectionAnalyzerTests.Reports_message_bus_and_other_use_case_dependencies`，
  驗證同一個 Use Case 的 `IMessageBus` 與另一個 `*UseCase` 相依會得到兩個
  `DBA1016`。

目前沒有各自針對 `IMediator`、`IDispatcher`、`*Dispatcher`、框架命名空間或抽象
類別例外的專屬測試；這些行為的精確邊界以實作中的條件為準。
