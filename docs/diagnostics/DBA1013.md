# DBA1013：Projection 不應執行持久化寫入

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1013</code>
- **標題**：Projection should not perform persistence writes
- **預設 severity**：<code>Warning</code>（預設啟用）

Projection 是讀取端 Port；它不應直接寫入持久化層。將寫入移出 Projection，可保持讀寫責任分離並降低讀模型更新帶來的副作用。

## 適用範圍與觸發條件

檢查已辨識為 projection 的型別內方法呼叫。`SaveChanges`／`SaveChangesAsync` 的 declaring type 為 db-context，或 Add／AddAsync／Update／Remove 的 declaring type 為 db-context／db-set 時回報。這裡 projection 指讀取端 port，不把 ES projector 更新 read model 自動套用為同一角色。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。未設定時採 legacy，以下名稱式範例以此相容模式為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

~~~csharp
public interface IProjection
{
}

public class DbContext
{
    public void SaveChanges()
    {
    }
}

public sealed class OrderProjection : IProjection
{
    private readonly DbContext dbContext = new();

    public void Execute()
    {
        dbContext.SaveChanges(); // DBA1013
    }
}
~~~

## 合規範例

~~~csharp
using System.Collections.Generic;

public interface IProjection
{
}

public sealed class OrderProjection : IProjection
{
    public void Execute(List<object> results, object item)
    {
        results.Add(item);
    }
}
~~~

<code>List&lt;T&gt;.Add</code> 的宣告型別不是 <code>DbContext</code> 或 <code>DbSet</code>，所以不會觸發。

## 修正指引

1. 從 Projection 移除 <code>SaveChanges</code>、<code>Add</code>、<code>Update</code>、<code>Remove</code> 等持久化寫入。
2. 將需要寫入的責任放入 Command、Use Case、Repository 或明確的寫入端處理流程。
3. 若 Projection 只需建構回應資料，改用記憶體集合、純 DTO 轉換或由呼叫端管理查詢結果。
4. 保留 Projection 的輸入與輸出為讀取端資料，不以 Projection 兼任投影更新或交易提交。

## 已知限制與例外

只檢查列出的已知寫入方法，不分析任意 SQL／批次 wrapper；普通 List<T>.Add 不視為 db-set。自有持久化型別需明確 mapping 或選用命名慣例。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1013.severity = warning
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1013`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
