# DBA1004：Controller 應宣告 ApiControllerAttribute

## 目的與預設嚴重性

此規則要求具體 API Controller 明確宣告 `ApiControllerAttribute`，使 API 慣例與驗證行為不依賴隱含設定。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1004` |
| Descriptor 標題 | `Controller should declare ApiControllerAttribute` |
| 類別 | `Architecture` |
| 預設嚴重性 | `warning` |
| 預設啟用 | 是 |

## 適用範圍與觸發條件

分析器只分析 C# 來源中的 `class` 宣告，且不分析產生的程式碼。class 名稱必須以大小寫相符的 `Controller` 結尾，且 class 不能是 `abstract`。

對符合條件的 class，分析器檢查該 class 的 attribute。若沒有任何 attribute 的語意類別名稱剛好為 `ApiControllerAttribute` 或 `ApiController`，就會在 class 名稱位置回報 `DBA1004`。

這是名稱式 attribute 判定：不要求繼承 `ControllerBase`、不檢查 ASP.NET Core namespace，也不要求 Controller 具有路由或 HTTP action。

## 違規範例

```csharp
public sealed class ResourceController
{
}
```

`ResourceController` 是具體 class，名稱又以 `Controller` 結尾，但沒有 `ApiControllerAttribute`，因此觸發 `DBA1004`。

## 合規範例

```csharp
using Microsoft.AspNetCore.Mvc;

[ApiController]
public sealed class ResourceController : ControllerBase
{
}
```

## 修正指引

1. 若此類別確實是 ASP.NET Core API Controller，直接在 class 上加入 `[ApiController]` 或 `[ApiControllerAttribute]`。
2. 若類別不是 API Controller，將其重新命名為不以 `Controller` 結尾的名稱，或改為適當的抽象基底／其他角色型別。
3. 不要只因缺少 attribute 而建立同名的自訂 attribute；應確認採用端引用正確的 Web framework 與 API 行為。

## 已知限制與例外

- 只用 class 名稱後綴與 attribute 類別的簡單名稱判定。自訂 namespace 中名為 `ApiControllerAttribute` 的 attribute 也會通過；反之，衍生但改名的等價 attribute 不會通過。
- 不會驗證是否實際承載 HTTP API、是否繼承 MVC 基底型別，或是否有 route／action；這些架構事實需由其他規則或人工審查確認。
- `abstract` Controller 完全略過，這是現行明確例外；同一個 `ControllerComplianceAnalyzer` 的其他 Controller 規則也不會分析它。
- 不提供 code fix、attribute 白名單或規則專屬的例外設定。若目標 Repository 根本不使用 API Controller Profile，可在該採用端停用規則，而非逐檔抑制。

## 設定與 Suppression

目前沒有規則專屬設定鍵。預設範本把 Controller Profile 的此規則設為 `warning`：

```editorconfig
[*.cs]
dotnet_diagnostic.DBA1004.severity = warning
```

不採用 API Controller 的目標 Repository 可在其架構設定中明確停用：

```editorconfig
[*.cs]
dotnet_diagnostic.DBA1004.severity = none
```

若只是一個暫時例外，使用最小範圍的 pragma 並記錄原因：

```csharp
#pragma warning disable DBA1004 // 過渡中的非 API Controller；追蹤項目：<id>
public sealed class LegacyController { }
#pragma warning restore DBA1004
```
