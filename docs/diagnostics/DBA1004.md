# DBA1004：Controller 應宣告 ApiControllerAttribute

## 目的與預設嚴重性

此規則要求具體 API Controller 明確宣告 `ApiControllerAttribute`，使 API 慣例與驗證行為不依賴隱含設定。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1004` |
| Descriptor 標題 | `Controller should declare ApiControllerAttribute` |
| 類別 | `Architecture` |
| 預設嚴重性 | `warning` |
| 預設啟用 | 是 |

## 設計理由與取捨

[Microsoft 的 ApiControllerAttribute 定義](../product/methodology-references.md#s9)是本規則的平台依據。產品選擇 Web API Controller 採用一致的 API 行為；這是平台採用慣例，與 DDD 或 Clean Architecture 的分層原則分開。

代價是端點必須接受並明確管理所選框架行為；Attribute 存在仍不證明完整輸入驗證。一般 MVC 與 Minimal API 的適用性需另辨。官方也支援繼承及 Assembly 層級的用法，現版直接 Attribute 短名檢查沒有完整涵蓋有效行為；細節見 [HTTP 政策與限制](../product/rule-design-rationale.md#http)。

## 適用範圍與觸發條件

檢查已辨識為 controller 的非抽象 class／record；型別可由 MVC ControllerBase、明確 mapping 或選用的命名慣例識別。若型別直接宣告的 attribute 中沒有簡單名稱為 `ApiControllerAttribute` 或 `ApiController` 的項目，便回報。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。目前未設定時採 `legacy`，以下名稱式範例以此預設為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

```csharp
public sealed class ResourceController
{
}
```

`ResourceController` 是具體 class，名稱又以 `Controller` 結尾，但沒有 `ApiControllerAttribute`，因此觸發 `DBA1004`。

## 合規範例

```csharp
using Microsoft.AspNetCore.Mvc;

[ApiController]
public sealed class ResourceController : ControllerBase
{
}
```

## 修正指引

1. 若此類別確實是 ASP.NET Core API Controller，直接在 class 上加入 `[ApiController]` 或 `[ApiControllerAttribute]`。
2. 若類別不是 API Controller，先確認 controller 角色來自名稱慣例、框架繼承或明確 mapping，再依實際架構修正 mapping、選擇適當 Profile、停用此規則或採最小範圍 suppression。重新命名不能移除 ControllerBase 繼承或明確 mapping 的角色證據。
3. 不要只因缺少 attribute 而建立同名的自訂 attribute；應確認採用端引用正確的 Web framework 與 API 行為。

## 已知限制與例外

attribute 判斷仍使用簡單名稱；自有同名 attribute 可通過。此規則不判定路由是否真的啟用，也不檢查 inherited／assembly-level ApiControllerAttribute；凡被辨識為 controller 且規則啟用者都可能受檢，尚未精確區分一般 MVC 與 API Controller。web-api Profile 的存在不會補足這項區分；abstract Controller 略過。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1004.severity = warning
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1004`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
