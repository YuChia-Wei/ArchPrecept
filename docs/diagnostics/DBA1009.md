# DBA1009：事件溯源 Aggregate 的狀態應透過事件轉換變更

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1009</code>
- **標題**：Event-sourced aggregate state should change through event transitions
- **預設 severity**：<code>Warning</code>（預設啟用）

事件溯源 Aggregate 的狀態變更必須可由事件重播得到相同結果。產品要求狀態變更經合法事件轉換；Analyzer 只豁免內建或精確映射 ES 根所宣告的 canonical `void When(TEvent)` virtual／abstract 方法及其真正 override 鏈，名稱本身不提供豁免。

## 設計理由與取捨

[Event Sourcing 的狀態重建及重播副作用分離](../product/rule-design-rationale.md#domain)支持事件化的狀態轉換。產品僅對 event-sourced-aggregate 選定合法 Transition 路徑，讓新行為與歷史重播能得到一致狀態；普通 Aggregate 不被迫採用事件溯源。

代價是事件演進及重建測試。重播不應產生新 pending 變更，儲存成功與提交確認也有不同責任；局部指派檢查雖會核對 transition 契約身分，仍無法證明 replay 正確性、儲存原子性或交易成功。

## 適用範圍與觸發條件

檢查已辨識為 event-sourced-aggregate 的型別中，方法內對 `this`／`base` instance 欄位／屬性的指派與遞增遞減，含 `>>>=`。以 Roslyn operation receiver 區分自身與其他實例；static 狀態不是此處的 instance state。方法外 initializer 與 constructor 不在此有界檢查內。

型別可由真正 EsAggregateRoot、自有 mapping 或明選命名慣例辨識；但 transition 豁免須有高信心的內建或精確映射根。自有 `event-sourced-aggregate` mapping 的根必須實際宣告非 static、回傳 void、單一非 ref 事件參數的 virtual／abstract `When`，衍生類別沿 override 鏈繼承該契約。不新增任意 transition selector，也不承認只有相同名稱的 overload／hidden 方法。`When` 內的 lambda／local function 是另一執行邊界，不因詞彙位置就豁免。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。目前未設定時採 `legacy`，以下名稱式範例以此預設為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

~~~csharp
public abstract class EsAggregateRoot<TId>
{
}

public sealed class Order : EsAggregateRoot<string>
{
    public string State { get; private set; } = "New";

    public void Confirm()
    {
        State = "Confirmed"; // DBA1009
    }
}
~~~

## 合規範例

~~~csharp
using ArchPrecept.Contracts.Domain;
using ArchPrecept.Contracts.Domain.EventSourcing;

public sealed class Order : EsAggregateRoot<string>
{
    public Order(string id) : base(id) { }
    public string State { get; private set; } = "New";

    public void Confirm() => Apply(new OrderConfirmed());

    protected override void When(IDomainEvent @event)
    {
        if (@event is OrderConfirmed) State = "Confirmed";
        else throw new System.ArgumentException("Unknown event", nameof(@event));
    }
}

public sealed class OrderConfirmed : IDomainEvent
{
    public System.Guid EventId { get; } = System.Guid.NewGuid();
    public System.DateTime OccurredOn { get; } = System.DateTime.UtcNow;
}
~~~

此例以實際 reference contract 的 override 表達 transition。若採 analyzer-only，自有根可用 metadata name＋assembly 精確映射，不需改繼承本產品類別。方法身分通過不是完整事件重播或儲存驗收。

## 修正指引

1. 在公開命令方法中建立並發佈代表狀態變更的領域事件。
2. 將欄位或屬性的直接指派移入實際 override 的 <code>When</code> transition；不要只把普通 helper 改名。
3. 保持事件重播與即時處理都走同一個狀態轉換路徑。
4. 若 Aggregate 並非事件溯源模型，請確認它不會因基底類別名稱誤被辨識為 <code>EsAggregateRoot</code>。

## 已知限制與例外

| 案例 | 本版結果與證明界線 |
| --- | --- |
| 內建或精確自有根的有效 override，含間接繼承 | 允許其中直接 instance state 指派 |
| 普通同名 When／不同參數 overload／hidden 方法 | 沒有 transition 豁免，直接修改自身狀態會報 |
| 其他實例成員／static 成員 | 不屬此規則自身 instance state 範圍 |
| Constructor／field 或 property initializer | 未分析，不代表重建 invariant 通過 |
| Collection.Add、索引、反射或 dynamic 修改 | 未分析，不代表沒有狀態變更 |
| When 呼叫 helper，helper 自己直接指派自身欄位 | 在 helper 指派處報告；不做呼叫鏈豁免或推論合法上下文 |
| 外部 helper 的間接副作用 | 不分析跨方法 effect，零診斷不是無副作用證明 |
| 未解析 mapping／不完整編譯 | 設定或編譯失敗，不當成已驗證合法 transition |

CT-005 的 apply、replay、append 與 commit 生命週期另由 Contracts tests 保護；MarkChangesAsCommitted 只檢查本機確認，不能證明外部儲存成功。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1009.severity = warning
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1009`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
