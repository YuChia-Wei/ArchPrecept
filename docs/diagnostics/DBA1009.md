# DBA1009：事件溯源 Aggregate 的狀態應透過事件轉換變更

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1009</code>
- **標題**：Event-sourced aggregate state should change through event transitions
- **預設 severity**：<code>Warning</code>（預設啟用）

事件溯源 Aggregate 的狀態變更必須可由事件重播得到相同結果。此規則要求受辨識的 Aggregate 將欄位或屬性變更集中在名稱為 <code>When</code> 的轉換方法中。

## 適用範圍與觸發條件

### 適用範圍

規則分析 C# 指派運算式與前置、後置遞增遞減運算式。它只會套用至繼承鏈中存在名稱正好為 <code>EsAggregateRoot</code> 的類別；產生程式碼不在範圍內。

### 精確觸發條件

下列條件全部成立時，會在被變更的成員位置回報 <code>DBA1009</code>：

1. 出現簡單、複合或 null-coalescing 指派，或前置／後置遞增遞減；
2. 變更發生於某個 <code>MethodDeclaration</code> 中，且該方法名稱不是 <code>When</code>；
3. 最接近的類別宣告所代表的型別，其基底型別鏈中有名稱為 <code>EsAggregateRoot</code> 的型別；
4. 目標語意符號是該 Aggregate 或其基底類別所宣告的欄位或屬性。

## 違規範例

~~~csharp
public abstract class EsAggregateRoot<TId>
{
}

public sealed class Order : EsAggregateRoot<string>
{
    public string State { get; private set; } = "New";

    public void Confirm()
    {
        State = "Confirmed"; // DBA1009
    }
}
~~~

## 合規範例

~~~csharp
public abstract class EsAggregateRoot<TId>
{
    protected void Raise(object @event)
    {
    }
}

public sealed class Order : EsAggregateRoot<string>
{
    public string State { get; private set; } = "New";

    public void Confirm() => Raise(new OrderConfirmed());

    private void When(OrderConfirmed @event)
    {
        State = "Confirmed";
    }
}

public sealed class OrderConfirmed
{
}
~~~

此規則只允許名稱為 <code>When</code> 的方法內直接變更狀態。

## 修正指引

1. 在公開命令方法中建立並發佈代表狀態變更的領域事件。
2. 將欄位或屬性的直接指派移入相應的 <code>When</code> 方法。
3. 保持事件重播與即時處理都走同一個狀態轉換路徑。
4. 若 Aggregate 並非事件溯源模型，請確認它不會因基底類別名稱誤被辨識為 <code>EsAggregateRoot</code>。

## 已知限制與例外

- 事件溯源識別只比較基底類別的簡單名稱；命名空間、泛型 arity 與實際事件溯源語意不參與判斷。
- 任何名稱正好為 <code>When</code> 的方法都被豁免；規則不驗證其參數、可見性或是否真的套用事件。
- 非 <code>When</code> 的轉換慣例（例如 <code>Apply</code>）仍會被回報，除非改為 <code>When</code> 或採用具理由的 suppression。
- 規則只檢查指派與遞增遞減，不會偵測集合的 <code>Add</code>、透過其他方法間接變更狀態，或驗證是否真的產生事件。
- 不屬於 Aggregate 本身或其基底類別的欄位與屬性不會由此規則回報。

## 設定與 Suppression

目前沒有 <code>DBA1009</code> 專屬設定；可在 <code>.editorconfig</code> 提高或降低通用 Roslyn severity：

~~~ini
[*.cs]
dotnet_diagnostic.DBA1009.severity = error
~~~

若正在遷移既有 Aggregate，suppression 應局限於最小程式碼區塊，並保留移除條件：

~~~csharp
#pragma warning disable DBA1009 // 遷移中的舊 Aggregate；完成事件轉換後移除。
State = restoredState;
#pragma warning restore DBA1009
~~~

可在專案檔廣域停用，但這會失去所有事件溯源 Aggregate 的防線：

~~~xml
<PropertyGroup>
  <NoWarn>$(NoWarn);DBA1009</NoWarn>
</PropertyGroup>
~~~
