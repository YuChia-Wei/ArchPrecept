# DBA1009：事件溯源 Aggregate 的狀態應透過事件轉換變更

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1009</code>
- **標題**：Event-sourced aggregate state should change through event transitions
- **預設 severity**：<code>Warning</code>（預設啟用）

事件溯源 Aggregate 的狀態變更必須可由事件重播得到相同結果。此規則要求受辨識的 Aggregate 將欄位或屬性變更集中在名稱為 <code>When</code> 的轉換方法中。

## 適用範圍與觸發條件

檢查已辨識為 event-sourced-aggregate 的型別中，方法內對自身或基底 instance 欄位／屬性的指派與遞增遞減。方法名稱為 `When` 時排除；方法外初始化與建構函式不在此語法檢查內。型別可由真正 EsAggregateRoot、自有 mapping 或相容命名慣例辨識。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。未設定時採 legacy，以下名稱式範例以此相容模式為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

~~~csharp
public abstract class EsAggregateRoot<TId>
{
}

public sealed class Order : EsAggregateRoot<string>
{
    public string State { get; private set; } = "New";

    public void Confirm()
    {
        State = "Confirmed"; // DBA1009
    }
}
~~~

## 合規範例

~~~csharp
public abstract class EsAggregateRoot<TId>
{
    protected void Raise(object @event)
    {
    }
}

public sealed class Order : EsAggregateRoot<string>
{
    public string State { get; private set; } = "New";

    public void Confirm() => Raise(new OrderConfirmed());

    private void When(OrderConfirmed @event)
    {
        State = "Confirmed";
    }
}

public sealed class OrderConfirmed
{
}
~~~

此規則只允許名稱為 <code>When</code> 的方法內直接變更狀態。

## 修正指引

1. 在公開命令方法中建立並發佈代表狀態變更的領域事件。
2. 將欄位或屬性的直接指派移入相應的 <code>When</code> 方法。
3. 保持事件重播與即時處理都走同一個狀態轉換路徑。
4. 若 Aggregate 並非事件溯源模型，請確認它不會因基底類別名稱誤被辨識為 <code>EsAggregateRoot</code>。

## 已知限制與例外

只辨識指定的 assignment 與 ++／--；不分析 collection.Add、方法呼叫導致的間接狀態變更，或 When 的實際 replay 正確性。名稱為 When 不等於證明有效事件轉換。CT-005 的生命週期另由 Contracts tests 保護。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1009.severity = warning
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1009`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
