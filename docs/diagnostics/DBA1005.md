# DBA1005：Controller 不應直接存取持久化

## 目的與預設嚴重性

此規則禁止 Controller 直接使用 `DbContext` 或呼叫 `SaveChanges`／`SaveChangesAsync`，使 HTTP 邊界只委派 Application 行為，而不承擔持久化責任。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1005` |
| Descriptor 標題 | `Controller should not access persistence directly` |
| 類別 | `Architecture` |
| 預設嚴重性 | `error` |
| 預設啟用 | 是 |

## 適用範圍與觸發條件

檢查已辨識為 controller 的非抽象 class／record。其型別語法參考 db-context 角色，或呼叫名稱為 `SaveChanges`／`SaveChangesAsync` 的方法時回報。方法解析失敗時仍可使用語法中的呼叫名稱；此後半條件不證明被呼叫者是真正資料庫。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。未設定時採 legacy，以下名稱式範例以此相容模式為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

```csharp
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;

[ApiController]
public sealed class ResourceController : ControllerBase
{
    private readonly AppDbContext dbContext;

    public ResourceController(AppDbContext dbContext)
    {
        this.dbContext = dbContext;
    }

    public void Save()
    {
        dbContext.SaveChanges();
    }
}

public sealed class AppDbContext : DbContext { }
```

`AppDbContext` 的型別使用與 `SaveChanges()` 呼叫都會觸發 `DBA1005`。

## 合規範例

```csharp
using Microsoft.AspNetCore.Mvc;

public interface ICreateResourceUseCase
{
    void Execute(string name);
}

[ApiController]
public sealed class ResourceController : ControllerBase
{
    private readonly ICreateResourceUseCase useCase;

    public ResourceController(ICreateResourceUseCase useCase)
    {
        this.useCase = useCase;
    }

    public void Create(string name)
    {
        useCase.Execute(name);
    }
}
```

持久化工作應由 Use Case、Repository 或 Infrastructure 實作承接，而非由 Controller 呼叫。

## 修正指引

1. 移除 Controller 對 `DbContext` 或其衍生型別的建構式、欄位、屬性與方法相依。
2. 以明確的 Use Case 介面注入 Application 邊界，將輸入轉交給 Use Case。
3. 將 `SaveChanges`／`SaveChangesAsync` 的交易與持久化安排移至 Use Case、Unit of Work 或 Infrastructure Repository。
4. 不要用在 Controller 內包裝或轉呼叫 `SaveChanges` 的私有方法規避規則；仍會按方法名稱回報。

## 已知限制與例外

呼叫 SaveChanges 的名稱式條件可能包含同名無關方法；不涵蓋所有持久化 API、SQL 或 runtime delegation。abstract Controller 與 generated code 排除。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1005.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1005`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
