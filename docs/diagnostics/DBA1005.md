# DBA1005：Controller 不應直接存取持久化

## 目的與預設嚴重性

此規則禁止 Controller 直接使用 `DbContext` 或呼叫 `SaveChanges`／`SaveChangesAsync`，使 HTTP 邊界只委派 Application 行為，而不承擔持久化責任。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1005` |
| Descriptor 標題 | `Controller should not access persistence directly` |
| 類別 | `Architecture` |
| 預設嚴重性 | `error` |
| 預設啟用 | 是 |

## 適用範圍與觸發條件

分析器只分析 C# 來源中非抽象、名稱以大小寫相符 `Controller` 結尾的 class。對每個符合條件的 class，出現以下任一情況便回報 `DBA1005`：

1. class 後代節點中的任一 `TypeSyntax` 解析到的型別，其自身或任一基底類別名稱剛好為 `DbContext`。這包含以 `DbContext` 為基底的 `AppDbContext`，以及直接使用 `DbContext` 的欄位、屬性、參數或其他型別語法。
2. class 後代節點中的任一方法呼叫，其語意方法名稱（無法解析時改用呼叫語法中的名稱）剛好為 `SaveChanges` 或 `SaveChangesAsync`。

每個符合的型別使用或呼叫位置都可各自產生一筆 Diagnostic；規則不要求它們實際來自 Entity Framework。

## 違規範例

```csharp
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;

[ApiController]
public sealed class ResourceController : ControllerBase
{
    private readonly AppDbContext dbContext;

    public ResourceController(AppDbContext dbContext)
    {
        this.dbContext = dbContext;
    }

    public void Save()
    {
        dbContext.SaveChanges();
    }
}

public sealed class AppDbContext : DbContext { }
```

`AppDbContext` 的型別使用與 `SaveChanges()` 呼叫都會觸發 `DBA1005`。

## 合規範例

```csharp
using Microsoft.AspNetCore.Mvc;

public interface ICreateResourceUseCase
{
    void Execute(string name);
}

[ApiController]
public sealed class ResourceController : ControllerBase
{
    private readonly ICreateResourceUseCase useCase;

    public ResourceController(ICreateResourceUseCase useCase)
    {
        this.useCase = useCase;
    }

    public void Create(string name)
    {
        useCase.Execute(name);
    }
}
```

持久化工作應由 Use Case、Repository 或 Infrastructure 實作承接，而非由 Controller 呼叫。

## 修正指引

1. 移除 Controller 對 `DbContext` 或其衍生型別的建構式、欄位、屬性與方法相依。
2. 以明確的 Use Case 介面注入 Application 邊界，將輸入轉交給 Use Case。
3. 將 `SaveChanges`／`SaveChangesAsync` 的交易與持久化安排移至 Use Case、Unit of Work 或 Infrastructure Repository。
4. 不要用在 Controller 內包裝或轉呼叫 `SaveChanges` 的私有方法規避規則；仍會按方法名稱回報。

## 已知限制與例外

- Controller 的辨識僅依名稱後綴；不驗證 namespace、MVC 繼承鏈、attribute 或路由。名稱相符但不是 Web Controller 的 class 也可能被分析。
- `DbContext` 辨識只檢查基底鏈的簡單名稱，不驗證 namespace 或套件。因此同名基底型別也可能被回報；其他不以 `DbContext` 表示的持久化技術不在此精確檢查範圍。
- `SaveChanges`／`SaveChangesAsync` 的呼叫以方法名稱判定。即使是 Controller 自己的私有 `SaveChanges` 方法，仍會被回報；現有測試已涵蓋此情況。
- 規則不做資料流、反射或 factory 分析，且不提供 code fix 或白名單例外。抽象 Controller 則完全略過。

## 設定與 Suppression

目前沒有規則專屬設定鍵。預設採用端範本為：

```editorconfig
[*.cs]
dotnet_diagnostic.DBA1005.severity = error
```

對無法立即重構且已取得架構核准的極小範圍，可暫時使用：

```csharp
#pragma warning disable DBA1005 // 過渡性持久化邊界；追蹤項目：<id>
// 最小必要的既有程式碼
#pragma warning restore DBA1005
```

`none`、`silent`、`suggestion`、`warning` 與 `error` 都可用，但全域停用會放棄 Controller 持久化邊界的機械化證據。
