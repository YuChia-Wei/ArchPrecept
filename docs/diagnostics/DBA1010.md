# DBA1010：Use Case 不應使用 Service Locator 或屬性注入

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1010</code>
- **標題**：Use case should not use service locator or attribute injection
- **預設 severity**：<code>Error</code>（預設啟用）

Use Case 與 Handler 的相依應在建構子中明確宣告。Service Locator 與屬性注入會隱藏相依關係，讓型別的協作需求無法從建構子與簽章直接判讀。

## 適用範圍與觸發條件

### 適用範圍

規則分析名稱以區分大小寫的 <code>UseCase</code> 或 <code>Handler</code> 結尾的 C# 類別；產生程式碼不在分析範圍內。

### 精確觸發條件

在適用型別中，符合下列任一情況即回報 <code>DBA1010</code>：

1. 欄位、屬性或任一方法參數（包括建構子參數）的型別名稱以 <code>ServiceLocator</code> 結尾。
2. 屬性套用了語意型別名稱為 <code>Inject</code>、<code>InjectAttribute</code>、<code>FromServices</code> 或 <code>FromServicesAttribute</code> 的 Attribute。

若成員型別是精確的 <code>System.IServiceProvider</code>，會由相鄰但不同的 <code>DBA1002</code> 回報，而不是 <code>DBA1010</code>。

## 違規範例

~~~csharp
using System;

public interface IOrderRepository
{
}

public sealed class InjectAttribute : Attribute
{
}

public sealed class PlaceOrderHandler
{
    [Inject]
    public IOrderRepository Repository { get; set; } = default!; // DBA1010
}
~~~

## 合規範例

~~~csharp
public interface IOrderRepository
{
}

public sealed class PlaceOrderHandler
{
    private readonly IOrderRepository repository;

    public PlaceOrderHandler(IOrderRepository repository)
    {
        this.repository = repository;
    }
}
~~~

建構子參數清楚列出 Handler 所需的協作項目，組合根則負責提供具體實作。

## 修正指引

1. 將 <code>[Inject]</code>、<code>[FromServices]</code> 等屬性注入改為建構子注入。
2. 以明確的 Port 或服務介面取代 Service Locator 型別，並把取得實作的責任留在 composition root。
3. 對 <code>IServiceProvider</code> 造成的診斷，依 <code>DBA1002</code> 的要求改為明確建構子相依。
4. 對每個相依重新檢視是否真為 Use Case 或 Handler 的責任，避免只是把 Service Locator 拆成過多相依。

## 已知限制與例外

- 型別與 Attribute 的判斷只比對簡單名稱，不檢查命名空間；同名但語意不同的型別或 Attribute 仍可能被回報。
- 只有屬性 Attribute 會觸發屬性注入檢查；欄位、方法或建構子上的 Attribute 不由此分支檢查。
- 未使用這四個 Attribute 名稱的自訂注入機制，以及未以欄位、屬性或參數型別宣告的 Service Locator 使用方式，可能不會被偵測。
- 名稱不以 <code>UseCase</code> 或 <code>Handler</code> 結尾的型別不在此規則範圍內。
- 現有測試直接覆蓋屬性注入；<code>ServiceLocator</code> 名稱後綴的行為來自 Analyzer 實作，尚無獨立測試案例。

## 設定與 Suppression

目前沒有 <code>DBA1010</code> 專屬設定。若團隊要在採用初期分階段導入，可在 <code>.editorconfig</code> 設定 severity：

~~~ini
[*.cs]
dotnet_diagnostic.DBA1010.severity = warning
~~~

若存在經審查且暫時無法改寫的框架整合，僅對最小範圍使用 suppression：

~~~csharp
public interface IOrderRepository
{
}

#pragma warning disable DBA1010 // 外部框架轉接層；替換計畫：...
[Inject]
public IOrderRepository Repository { get; set; } = default!;
#pragma warning restore DBA1010
~~~

廣域停用會失去所有 Use Case／Handler 的此項防線，僅應在明確治理決策下使用：

~~~xml
<PropertyGroup>
  <NoWarn>$(NoWarn);DBA1010</NoWarn>
</PropertyGroup>
~~~
