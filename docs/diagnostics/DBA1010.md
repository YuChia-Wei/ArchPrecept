# DBA1010：Use Case 不應使用 Service Locator 或屬性注入

## 目的與預設嚴重性

- **Diagnostic ID**：<code>DBA1010</code>
- **標題**：Use case should not use service locator or attribute injection
- **預設 severity**：<code>Error</code>（預設啟用）

Use Case 與 Handler 的相依應在建構子中明確宣告。Service Locator 與屬性注入會隱藏相依關係，讓型別的協作需求無法從建構子與簽章直接判讀。

## 設計理由與取捨

[明確相依與高層政策對抽象的依賴](../product/rule-design-rationale.md#application)支持建構時提供必要協作者。產品禁止以 Service Locator 或屬性注入隱藏 Use Case／Handler 所需能力，避免流程依容器當時狀態才決定可用服務。

代價是必須顯式組裝，既有框架自動注入方式也需留在適當 Adapter。現版 Locator 尾碼及 Attribute 短名是判定近似；無關同名型別不等於真實注入能力，未辨識查找亦不等於合法。

## 適用範圍與觸發條件

檢查已辨識為 use-case 或 handler 的 class／record／struct。直接欄位、屬性、方法／建構函式參數的型別名稱以 `ServiceLocator` 結尾，或屬性 attribute 的簡單名稱為 Inject／InjectAttribute／FromServices／FromServicesAttribute 時回報。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。目前未設定時採 `legacy`，以下名稱式範例以此預設為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

~~~csharp
using System;

public interface IOrderRepository
{
}

public sealed class InjectAttribute : Attribute
{
}

public sealed class PlaceOrderHandler
{
    [Inject]
    public IOrderRepository Repository { get; set; } = default!; // DBA1010
}
~~~

## 合規範例

~~~csharp
public interface IOrderRepository
{
}

public sealed class PlaceOrderHandler
{
    private readonly IOrderRepository repository;

    public PlaceOrderHandler(IOrderRepository repository)
    {
        this.repository = repository;
    }
}
~~~

建構子參數清楚列出 Handler 所需的協作項目，組合根則負責提供具體實作。

## 修正指引

1. 將 <code>[Inject]</code>、<code>[FromServices]</code> 等屬性注入改為建構子注入。
2. 以明確的 Port 或服務介面取代 Service Locator 型別，並把取得實作的責任留在 composition root。
3. 對 <code>IServiceProvider</code> 造成的診斷，依 <code>DBA1002</code> 的要求改為明確建構子相依。
4. 對每個相依重新檢視是否真為 Use Case 或 Handler 的責任，避免只是把 Service Locator 拆成過多相依。

## 已知限制與例外

ServiceLocator 與 injection attribute 仍以名稱判定，不推論任意方法內的服務解析，也不涵蓋 DI 容器全部功能。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1010.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1010`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
