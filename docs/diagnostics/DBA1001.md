# DBA1001：儲存庫合約違規

## 目的與預設嚴重性

此規則維持 Aggregate Repository、Query Repository 與相容性 Repository 合約的語意邊界，避免通用可寫入 CRUD 介面、非 Aggregate Root 型別，或將讀取與寫入混在同一個 Query Repository 中。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1001` |
| Rule ID | `AP-REPOSITORY-001` |
| Profile | `legacy`、`core`；其他 Profile 可用個別 Rule 明確啟用 |
| Descriptor 標題 | `Repository contract violation` |
| 類別 | `Architecture` |
| 預設嚴重性 | `error` |
| 預設啟用 | 是 |

## 設計理由與取捨

[Aggregate／Repository、CQRS 與窄 Port 原則](../product/rule-design-rationale.md#repository)支持把領域更新與條件查詢分責。ArchPrecept 再選定 Aggregate Root 專用的 `FindByIdAsync`／`SaveAsync`，避免查詢需求膨脹到寫入 Port，或可寫 Entity CRUD 繞過 Aggregate 不變條件。方法集合是產品收斂，並非 DDD 作者規定的唯一 Repository 形式。

代價是大量逐筆載入可能增加 I/O；有實際需求時以明確有界的批次能力處理。條件查詢回傳候選 ID 後，命令仍須重新載入並檢查目前狀態；批次存取不等於跨 Aggregate 原子交易。現版只檢查下述宣告子集，不能證明副作用或儲存正確。

## 適用範圍與觸發條件

檢查已辨識的 repository 介面、class／record／struct。`generic-repository` 的泛型介面禁止使用；`compatibility-repository` 必須繼承 aggregate-repository。介面檢查直接與繼承後的有效普通方法，保留每個 port 的泛型替換；不把第一個 Aggregate／ID 配對套用到其他 port。來源外介面的方法定位到實作它的 adapter，來源內繼承違規定位到暴露該能力的介面。

聚合 repository 的兩個泛型引數依序為 Aggregate 與 ID。方法限 instance、非泛型、非 ref-return 的 `FindByIdAsync`／`SaveAsync`；第一個參數分別為該 port 的 ID／Aggregate，回傳分別為 BCL `Task<TAggregate>`／`Task`。可有第二個 BCL `CancellationToken` 參數；不接受 ref／out／in／params。BCL 判定使用符號及核心組件身分，consumer 自行宣告的 `System.Threading.Tasks.Task` 不符合。當 Aggregate 的泛型 identity 契約可辨識時，port ID 必須一致；純 marker 沒有可讀 identity 引數時不宣稱已證明 identity 一致。

query-repository 的有效方法不得使用 Save／Add／Create／Insert／Update／Delete／Remove／Upsert／Persist／Purge 前綴；回傳型別及陣列／泛型引數不得包含辨識出的 Aggregate／Entity。這是宣告型別與動詞政策，並不執行方法本體。

同一 adapter 可實作分離的 Aggregate 與 query 窄 port，包括顯式實作及基底提供的實作。每個方法依 Roslyn 的 interface implementation mapping 對應其 port，不因合法方法聯集誤報。未對應任何窄 port 的額外公開方法仍依 concrete repository 角色檢查。把 Aggregate 與 query 合成同一介面會在該介面的有效視圖暴露讀寫能力，不因兩個角色同時存在而豁免。

0.0.3 起，角色由共用 `RoleClassifier` 辨識：明確 mapping → 內建／繼承契約 → 可選命名慣例。所有一般規則略過 generated code。目前未設定時採 `legacy`，以下名稱式範例以此預設為前提；選定 Profile 與規則適用性見 [設定與角色契約](../product/analyzer-policy.md) 與 [唯一 Catalog](../../rules/catalog.xml)。

## 違規範例

```csharp
using System.Threading.Tasks;

public abstract class AggregateRoot<TId> { }
public sealed class Order : AggregateRoot<string> { }

// 泛型 CRUD 介面：直接觸發 DBA1001。
public interface IRepository<TEntity, TId>
{
    void Save(TEntity entity);
}

public interface IAggregateRepository<TAggregate, TId>
    where TAggregate : AggregateRoot<TId>
{
}

// 聚合儲存庫額外宣告 FindByStatusAsync：觸發 DBA1001。
public interface IOrderRepository : IAggregateRepository<Order, string>
{
    Task<Order> FindByStatusAsync(string status);
}

public interface IQueryRepository { }

// Query Repository 宣告寫入方法：觸發 DBA1001。
public interface IOrderQueryRepository : IQueryRepository
{
    Task UpdateStatusAsync(string id);
}
```

## 合規範例

```csharp
using System.Threading;
using System.Threading.Tasks;

public abstract class AggregateRoot<TId> { }
public sealed class Order : AggregateRoot<string> { }
public sealed record OrderSummary(string Id, string Status);

public interface IAggregateRepository<TAggregate, TId>
    where TAggregate : AggregateRoot<TId>
{
    Task<TAggregate> FindByIdAsync(TId id, CancellationToken cancellationToken);
    Task SaveAsync(TAggregate aggregate, CancellationToken cancellationToken);
}

public interface IOrderRepository : IAggregateRepository<Order, string> { }

public interface IQueryRepository { }

public interface IOrderQueryRepository : IQueryRepository
{
    Task<OrderSummary> FindSummaryAsync(string id);
}
```

## 修正指引

1. 將通用可寫入 CRUD 介面拆成以 Aggregate 為單位的 Repository；其他能力依實際責任設計窄 Port，不以改名繞過 Aggregate 不變條件。
2. 若使用現行 `compatibility-repository` 角色，其合約須繼承 aggregate-repository；例如目前的 `IDomainRepository<TAggregate, TId>` 須繼承 `IAggregateRepository<TAggregate, TId>`。這是現版該角色的條件，不要求為新合約建立相容介面。
3. 將 Aggregate Repository 縮回 `FindByIdAsync` 與 `SaveAsync`，並使參數與 `Task` 回傳型別符合規定。批次或條件查詢應以不同的目標專用 Port 表達。
4. 讓 Query Repository 只回傳 Read Model、識別碼或純量；將寫入行為移至 Application／Use Case 邊界與 Aggregate Repository。

下列 adapter 組合合法；consumer 是否可以直接依賴 `Store`，仍取決於該入口的政策及實際暴露能力。Controller 的明選純查詢例外必須依賴 `IOrderQueryRepository` 等 query-only 視圖，不能因 `Store` 也實作 query port 就繞過其寫入能力。

```csharp
public sealed class Store : IOrderRepository, IOrderQueryRepository
{
    public Task<Order> FindByIdAsync(string id, CancellationToken ct) => throw new NotImplementedException();
    public Task SaveAsync(Order aggregate, CancellationToken ct) => throw new NotImplementedException();
    public Task<OrderSummary> FindSummaryAsync(string id) => throw new NotImplementedException();
}
```

## 已知限制與例外

DBA1001 檢查方法契約；query 參數物件的內部內容、property／field 本體、任意 helper effect、I/O、交易及儲存成功不在其證明範圍內。不要求每個 marker 直接重複宣告方法，不以空 marker 證明具備完整可呼叫 Repository API。聚合 repository 的兩參數順序與 Task 簽章是本產品契約，並非所有 repository 設計的必要形狀。回傳型別的泛型遞迴是宣告型別限制，不能推論 wrapper 是否真的保存該值。

與入口規則共用的 query-only 視圖額外拒絕混合 Aggregate／generic writable role、integration-event-publisher／outbox-port、寫入方法、Entity／Aggregate 回傳、ref-return 方法／property、可公開寫入的 property／field、event，以及透過 getter／indexer／回傳型別傳出的 Repository／DomainService／UseCase／Handler／bus／transport／Domain event dispatcher／integration-event-publisher／outbox-port 能力。型別檢查沿陣列與泛型引數，不探索任意 DTO 物件圖；readonly/read-only 不免除型別檢查。unresolved 或設定錯誤不構成 query-only 證據。這項有界檢查不是 query 方法的副作用分析，也不自行代表入口已明選純查詢例外。

相對已發布 `0.0.3-preview`，本候選修正了僅直接成員、第一個泛型配對、顯式實作漏判與合法多 port adapter 方法聯集誤報。保持 Rule／Diagnostic ID、Profile 與預設 Error；不提供平行舊 predicate。此頁描述目前來源候選，不表示已上傳新套件；固定已發布版本的來源與文件由對應版本 provenance tag 定位。

診斷 properties 記錄 ruleId、role、roleEvidence、confidence 與型別。命名慣例是低信心證據；零診斷不能當成完整架構合格。需要覆蓋證據時用 `Expected` 明確宣告範圍，未辨識／generated／停用分別由 DBA0002 回報；載入或設定失敗另處理。

## 設定與 Suppression

可用兩層 AdditionalFiles 設定 Profile、明確角色及單一規則 enabled／severity；設定格式與優先序見 [採用政策](../product/analyzer-policy.md)。標準 Roslyn severity 最後套用，但不會自行啟用被 Profile 排除的規則。

```ini
[*.cs]
dotnet_diagnostic.DBA1001.severity = error
```

可選 none／silent／suggestion／warning／error。暫時例外可使用最小範圍的 `#pragma warning disable DBA1001`／restore，並留下理由；不要以改名或整個 repository suppression 代替確認角色。
