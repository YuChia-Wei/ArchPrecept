# DBA1001：儲存庫合約違規

## 目的與預設嚴重性

此規則維持 Aggregate Repository、Query Repository 與相容性 Repository 合約的語意邊界，避免通用可寫入 CRUD 介面、非 Aggregate Root 型別，或將讀取與寫入混在同一個 Query Repository 中。

| 項目 | 值 |
| --- | --- |
| Diagnostic ID | `DBA1001` |
| Descriptor 標題 | `Repository contract violation` |
| 類別 | `Architecture` |
| 預設嚴重性 | `error` |
| 預設啟用 | 是 |

## 適用範圍與觸發條件

分析器只分析 C# 的介面型別，且不分析產生的程式碼。所有合約辨識都以原始定義的**簡單名稱與泛型 arity** 為準，不限制 namespace。

符合下列任一條件即回報 `DBA1001`：

1. 介面是泛型介面，且原始名稱剛好為 `IRepository`、`IGenericRepository`、`IWritableRepository` 或 `ICrudRepository`。
2. 介面本身或其繼承介面為 `IAggregateRepository<TAggregate, TId>` 或 `IDomainRepository<TAggregate, TId>`，且發生下列任一情況：
   - `IDomainRepository<TAggregate, TId>` 沒有透過繼承鏈實作 `IAggregateRepository<TAggregate, TId>`。
   - 第一個 Aggregate 型別引數無法被辨識為 Aggregate Root。現行辨識接受基底類別名稱為 `AggregateRoot` 或 `EsAggregateRoot`，或介面名稱為 `IAggregateRoot`。
   - 介面**直接宣告**的普通方法名稱不是 `FindByIdAsync` 或 `SaveAsync`。
   - 上述兩個允許的方法不符合下列形狀：恰有一個主參數，或再加一個型別為 `System.Threading.CancellationToken` 的第二參數；`FindByIdAsync` 接受 `TId` 並回傳 `System.Threading.Tasks.Task<TAggregate>`，`SaveAsync` 接受 `TAggregate` 並回傳非泛型 `Task`。第二個 `CancellationToken` 是否 optional 不在此規則的驗證範圍內；參考型別的 nullable 註記也不另行區分。
3. 介面本身或其繼承介面為非泛型 `IQueryRepository`，且其**直接宣告**的普通方法發生下列任一情況：
   - 方法名稱以大小寫相符的 `Save`、`Add`、`Create`、`Insert`、`Update`、`Delete`、`Remove`、`Upsert`、`Persist` 或 `Purge` 開頭。
   - 回傳型別本身或任何泛型型別引數可被辨識為 Aggregate Root 或 Domain Entity。Domain Entity 的現行辨識為基底類別名稱 `DomainEntity` 或介面名稱 `IDomainEntity`。

## 違規範例

```csharp
using System.Threading.Tasks;

public abstract class AggregateRoot<TId> { }
public sealed class Order : AggregateRoot<string> { }

// 泛型 CRUD 介面：直接觸發 DBA1001。
public interface IRepository<TEntity, TId>
{
    void Save(TEntity entity);
}

public interface IAggregateRepository<TAggregate, TId>
    where TAggregate : AggregateRoot<TId>
{
}

// 聚合儲存庫額外宣告 FindByStatusAsync：觸發 DBA1001。
public interface IOrderRepository : IAggregateRepository<Order, string>
{
    Task<Order> FindByStatusAsync(string status);
}

public interface IQueryRepository { }

// Query Repository 宣告寫入方法：觸發 DBA1001。
public interface IOrderQueryRepository : IQueryRepository
{
    Task UpdateStatusAsync(string id);
}
```

## 合規範例

```csharp
using System.Threading;
using System.Threading.Tasks;

public abstract class AggregateRoot<TId> { }
public sealed class Order : AggregateRoot<string> { }
public sealed record OrderSummary(string Id, string Status);

public interface IAggregateRepository<TAggregate, TId>
    where TAggregate : AggregateRoot<TId>
{
    Task<TAggregate> FindByIdAsync(TId id, CancellationToken cancellationToken);
    Task SaveAsync(TAggregate aggregate, CancellationToken cancellationToken);
}

public interface IOrderRepository : IAggregateRepository<Order, string> { }

public interface IQueryRepository { }

public interface IOrderQueryRepository : IQueryRepository
{
    Task<OrderSummary> FindSummaryAsync(string id);
}
```

## 修正指引

1. 將通用可寫入 CRUD 介面拆成以 Aggregate 為單位的 Repository，或改成不屬於此四個保留名稱的目標專用能力 Port。
2. 讓 `IDomainRepository<TAggregate, TId>` 繼承 `IAggregateRepository<TAggregate, TId>`；新合約優先直接採用後者。
3. 將 Aggregate Repository 縮回 `FindByIdAsync` 與 `SaveAsync`，並使參數與 `Task` 回傳型別符合規定。批次或條件查詢應以不同的目標專用 Port 表達。
4. 讓 Query Repository 只回傳 Read Model、識別碼或純量；將寫入行為移至 Application／Use Case 邊界與 Aggregate Repository。

## 已知限制與例外

- 規則使用簡單名稱與 arity，而非 namespace、特定基底組件或設定檔。因此不同 namespace 中同名的介面也會被納入；反之，改名的等價合約不會被辨識。
- 對 Aggregate Repository 與 Query Repository，只檢查目前介面直接宣告的普通方法，不會再次檢查繼承而來的成員，也不檢查 Query 方法的參數型別。
- Aggregate 方法只接受 `Task`／`Task<T>`，不接受 `ValueTask` 或其他非同步抽象；這是現行實作的合約限制，而非一般 C# 慣例。
- `IRepository` 等四個保留名稱只要是泛型介面就會被回報，實作沒有額外檢查介面可見性或是否真的含有寫入成員。
- 沒有屬性、註解或專用設定可讓單一 Repository 合約自動豁免。若架構確實需要不同模型，應採用明確的目標專用 Port，或保留範圍狹小且附理由的 suppression。

## 設定與 Suppression

目前分析器未定義規則專屬的 `.editorconfig` option key；可使用 Roslyn 的嚴重性設定：

```editorconfig
[*.cs]
dotnet_diagnostic.DBA1001.severity = error
```

可用的值包括 `none`、`silent`、`suggestion`、`warning` 與 `error`。若必須針對少量既有程式碼暫時抑制，將範圍限制在最小區塊並留下可追溯原因：

```csharp
#pragma warning disable DBA1001 // 例外原因與追蹤項目
// 已核准的過渡性合約
#pragma warning restore DBA1001
```

避免把可修正的 Aggregate／Query 邊界問題設為全域 `none`；目標 Repository 的 `templates/analyzer-severity.editorconfig` 已提供各 Diagnostic 可獨立調整的範例。
