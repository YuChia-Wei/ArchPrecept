# 0.0.6-preview

2026-11-25 已發布至 GitHub Packages，七個 `0.0.6-preview` 套件皆為 public，均連結 ArchPrecept repository。本版供既有專案在進入 `0.1.0` 前試裝。[套件發布與 registry 驗證](https://github.com/YuChia-Wei/ArchPrecept/actions/runs/45647944798) · [上一個版本](0.0.5-preview.md)

## 從 0.0.5-preview 升級

- **Domain 與事件溯源**。只需要識別的 Entity 可以繼續用 `DomainEntity<TId>`。一般 Entity 若要編輯事件緩衝，改用 `BufferedDomainEntity<TId>` 或明確依賴 `IDomainEventBuffer`。普通 Aggregate 保留緩衝操作，ES 儲存端改用 `IESAggregateRoot<TId>` 讀 pending，append 成功後確認版本。升級者須重新編譯。[能力矩陣與 API 差異](../product/event-sourcing-contract.md)
- **既有專案**。以 `0` 表示尚未持久化的 Web API 模型須明確初始化，該 lab 的原有 34 項測試已通過。MQ 自有契約案例保留同一交易 adapter，分別透過 query、write、commit ports 存取。支援的 Analyzer predicate 與設定沿用上一版。[Web API 採用驗證](0.0.6-consumer-validation.md) · [MQ 判讀與驗證](mq-repository-adoption.md)
- **範本**。除了 starter 與純量 VO，現在可個別加入 Aggregate、Domain Event、UseCase、Repository／query port、Mapper、HTTP Controller、host-neutral Handler 及可貼入既有介面的 `ExecuteAsync` 宣告。既有專案使用明確名稱與角色 mapping，生成後自行完成業務行為與宿主註冊。[範本命令與使用方式](../templates.md)
- **架構測試**。`ap-boundary-test` 為既有 xUnit 專案產生直接組件依賴測試，可指定來源與禁止目標。測試涵蓋編譯後實際參考的組件；傳遞依賴與未使用的 ProjectReference 留在此檢查範圍外。[使用範例](../architecture-testing.md)

## 專案試裝

先在試用專案的分支設定有讀取權限的 GitHub Packages source。選用 Analyzer／Contracts 時只更新該專案實際用到的 PackageReference，精確指定 `[0.0.6-preview]`，再執行 `dotnet restore`、`dotnet build` 與既有的 `dotnet test`。要新增骨架時，使用相同版本的 SDK 範本：

```sh
dotnet new install ArchPrecept.Templates::0.0.6-preview
dotnet new list ap-
```

兩個支援的 consumer SDK 為 .NET 8 與 10。使用 reference contracts 的既有專案應特別檢查 Id 初始化、事件收集與提交；使用自有契約的專案可沿用原模型，檢查角色 mapping 與測試結果。解除範本安裝保留生成的原始碼。[安裝來源與套件選擇](../getting-started.md)

## 發布前驗證

本機已以 SDK 11.0.100 建置七包。Analyzer 251 項測試通過，Domain／ES 在 net8.0 與 net10.0 各 26 項通過。SDK 8.0.428／10.0.404 在隔離快取驗證套件使用方式、19 條 Analyzer 規則及範本的 reference／custom 模式。HTTP、query port、UseCase 片段與組件邊界的故意違規均產生預期失敗，修復後可重新建置或通過測試。
