# 0.0.6-preview

2026-11-25，七個套件於 GitHub Packages 公開發布，並以 .NET SDK 8 與 10 完成安裝驗收。[套件發布](https://github.com/YuChia-Wei/ArchPrecept/actions/runs/45647944798) · [上一個版本](0.0.5-preview.md)

## 從 0.0.5-preview 升級

- **Domain 與事件溯源**。只需要識別的 Entity 可以繼續用 `DomainEntity<TId>`。一般 Entity 若要編輯事件緩衝，改用 `BufferedDomainEntity<TId>` 或明確依賴 `IDomainEventBuffer`。普通 Aggregate 保留緩衝操作，ES 儲存端改用 `IESAggregateRoot<TId>` 讀 pending，append 成功後確認版本。升級者須重新編譯。[能力矩陣與 API 差異](../product/event-sourcing-contract.md)
- **既有專案**。以 `0` 表示尚未持久化的模型須明確初始化。自有契約可由同一交易 adapter 實作 query、write 和 commit ports，由呼叫端依所需能力選用。Analyzer 判定與設定沿用上一版。
- **範本**。除了 starter 與純量 VO，現在可個別加入 Aggregate、Domain Event、UseCase、Repository／query port、Mapper、HTTP Controller、host-neutral Handler 及可貼入既有介面的 `ExecuteAsync` 宣告。既有專案使用明確名稱與角色 mapping，生成後自行完成業務行為與宿主註冊。[範本命令與使用方式](../templates.md)
- **架構測試**。`ap-boundary-test` 為既有 xUnit 專案產生直接組件依賴測試，可指定來源與禁止目標。測試涵蓋編譯後實際參考的組件；傳遞依賴與未使用的 ProjectReference 留在此檢查範圍外。[使用範例](../architecture-testing.md)

## 專案試裝

GitHub Packages 的來源為 `https://nuget.pkg.github.com/YuChia-Wei/index.json`。本機使用有套件讀取權限的 GitHub 憑證，Actions 可使用有權限的 `GITHUB_TOKEN`。透過既有 NuGet credential provider 或使用者層級的來源設定提供憑證。使用 source mapping 的專案，請將 `ArchPrecept.*` 對應到此來源。若自行建置，則可使用 `eng/Build-Packages.ps1` 的本機 nupkg 輸出目錄。[GitHub NuGet registry 驗證說明](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-nuget-registry)

在專案檔精確指定所需套件。例如只裝 Analyzer 時，加入下列項目後執行 `dotnet restore`、`dotnet build` 與既有的 `dotnet test`。

```xml
<ItemGroup>
  <PackageReference Include="ArchPrecept.Analyzers.Core" Version="[0.0.6-preview]" PrivateAssets="all" />
</ItemGroup>
```

要新增骨架時，使用相同版本的 SDK 範本：

```sh
dotnet new install ArchPrecept.Templates::0.0.6-preview
dotnet new list ap-
```

兩個支援的 consumer SDK 為 .NET 8 與 10。使用 reference contracts 的既有專案應特別檢查 Id 初始化、事件收集與提交；使用自有契約的專案可沿用原模型，檢查角色 mapping 與測試結果。解除範本安裝保留生成的原始碼。[安裝來源與套件選擇](../getting-started.md)
