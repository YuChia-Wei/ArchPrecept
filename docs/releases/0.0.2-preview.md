# 0.0.2-preview 候選變更

狀態：2026-10-21，本機候選，尚未發布。需求依據為 [CT-004／CT-005](../product/prd.md)，
本次不新增 Issue。完整 API、行為與遷移說明見 [ES 核心契約](../product/event-sourcing-contract.md)
與 [Messaging 責任與遷移](../product/messaging-contract.md)。

## 版本建議

這次建議採 `0.0.2-preview`，並已用於本機建置候選。
`0.0.1-preview.2` 適合仍以 0.0.1 為目標的預覽修訂；此次增加可獨立安裝的套件，
移動公開型別並調整建構／重播與事件變更行為，另設 0.0.2 預覽基線較容易追蹤遷移。
這是產品在 0.x 初期的版本選擇，不是 SemVer 強制規則，也不表示 patch 向下相容。
兩種格式都合法；[SemVer §4／§9](https://semver.org/spec/v2.0.0.html) 允許初期 0.x API 變動，
且預覽版不保證穩定。正式版政策仍另行決定。

六個套件沿用共同 release train：`ArchPrecept.Contracts.Domain`、`ArchPrecept.Contracts.Application`、
`ArchPrecept.Contracts.Messaging`、`ArchPrecept.Contracts.Application.Messaging`、
`ArchPrecept.Contracts.Domain.EventSourcing` 與 `ArchPrecept.Analyzers.Core`。
只想使用一般 Domain／Analyzer 的消費端不需安裝 ES 或 Messaging。
已發布的 `0.0.1-preview` bytes 保持不變。

## 相容性變更

本次相容性比較範圍為 CT-004／CT-005 直接影響的公開／受保護 API，對照既有 `0.0.1-preview`
來源與本次候選；不是全產品二進位相容性認證。

| API／行為 | 0.0.1-preview | 0.0.2-preview 候選 | 遷移影響 |
|---|---|---|---|
| `EsAggregateRoot<TId>` | Domain assembly／namespace | Domain.EventSourcing assembly／namespace，仍繼承 AggregateRoot | 新增 PackageReference、調整 using、重新編譯；無 type forwarder |
| 歷史建構子 | `EsAggregateRoot(IEnumerable<IDomainEvent>)` 立即重播 | 移除；新增 `LoadFromHistory` | 衍生初始化完成後明確載入 |
| 一般建構子 | 受保護無參數建構子 | 保留；另提供 `EsAggregateRoot(TId)` | 既有無參數建立方式可保留 |
| Domain 三個事件 mutator | 非 virtual | virtual；一般 Domain 行為保留 | ES 的 sealed override 拒絕直接變更；通用清除流程需改用 commit |
| `Apply`／`When`／`GetLastDomainEvent` | 同名受保護方法 | 簽章保留 | 加入失敗實例與重入防護；失敗後丟棄實例 |
| `MarkChangesAsCommitted(int)` | 版本算術檢查後清除 | 簽章與成功語意保留，另拒絕失敗／轉換中實例 | 仍由 adapter 負責原子 append 與 expected revision |
| DBA1001–DBA1017 | 既有 17 個 Diagnostic | ID、severity、規則實作不變 | 套件 consumer 驗證新 ES assembly 仍可被 DBA1009 辨識 |
| `IIntegrationEvent`／`IRequestContract` | Messaging.Abstractions | Messaging | 成員保留，更新引用與 namespace |
| `IIntegrationEventPublisher`／`IntegrationMessageDelivery` | Messaging.Abstractions | Application.Messaging | overload／record 形狀及預設委派保留；不保證預設處理 metadata |
| `MessagingTransportOptions`／`MessagingTransportProfile` | 隨契約套件發布 | 移到不發布的 host 參考範例 | 消費端接管設定類別與 Configuration 相依 |

先前尚未發布的 `ArchPrecept.Contracts.EventSourcing` 候選名稱已統一為
`ArchPrecept.Contracts.Domain.EventSourcing`，包含測試專案、namespace、範例、封裝與 workflow。
舊 `Messaging.Abstractions` 不產生相容轉接套件。保留型別成員不代表 assembly／namespace 身分相容；
必須重新編譯，使用儲存型別名稱的序列化器另行處理映射。

沒有新增儲存 adapter、schema migration、snapshot、投影執行器或 Analyzer 規則。

## 驗證方式與結果

在新的輸出目錄執行：

```powershell
./eng/Build-Packages.ps1 -OutputDirectory artifacts/review-0.0.2-preview
./eng/Test-PackageConsumer.ps1 -SdkMajor 8 -PackageDirectory artifacts/review-0.0.2-preview
./eng/Test-PackageConsumer.ps1 -SdkMajor 10 -PackageDirectory artifacts/review-0.0.2-preview
```

2026-10-21 本輪更名與 Messaging 拆分後，Windows 本機驗證完成：

| 驗證 | 結果 |
|---|---|
| Release build，SDK 10.0.303 | 成功，0 errors |
| Analyzer 測試 | 51 passed，0 failed／skipped |
| Domain.EventSourcing 行為測試 | .NET 8／10 各 21 passed，0 failed／skipped |
| 六套件封裝 | Package ID、assembly 路徑、metadata、精確相依集合、license 與 SHA-256 檢查通過 |
| SDK 8.0.426 consumer | 六種採用模式均通過，含相依隔離、JSON、發布 port、host 設定與 DBA1001／DBA1009 |
| SDK 10.0.402 consumer | 同上，使用另一組獨立 cache |

六種模式為 Analyzer-only、一般 Contracts、Domain.EventSourcing、訊息契約、Publisher、host 設定。
Messaging 可不安裝 Application.Messaging；兩者皆不引入 Domain、Analyzer 或 Configuration。
Host 設定只作合成正反例驗證，沒有連線 broker。
Code review 修正後再次執行上述驗證，結果同表，共 93 次測試執行、兩個 SDK 各六種消費模式通過。
本輪 consumer 使用精確 Package ID mapping。最終六個 nupkg 與 `SHA256SUMS`
位於 `artifacts/review-0.0.2-preview/`；它們是本機工作樹驗證候選，不是正式發布輸入。
先前五套件的結果不作為本輪證據；舊候選目錄保留但不是本輪發布輸入。

首次 sandbox 內的 SDK 啟動受到 Windows Service Control Manager 權限限制；
本輪 build／consumer 在允許的 sandbox 外執行完成，未修改 SDK 或系統服務設定。

本機驗證不代表 hosted CI、GitHub Packages registry restore、真實 Event Store 整合，
也不代表 Lab 已遷移。發布 workflow 的本機定義已納入六個現行套件，沒有觸發發布或修改遠端發布開關。
既有 private visibility 檢查仍保留；歷史上四個套件的 public 結果見 [0.0.1 發布紀錄](preview.md)，
在未完成發布可見性設定前不應啟動新版本發布。

## 本次 code review

Review 範圍為 CT-004／CT-005 的工作樹相對已發布來源 API：型別身分、Publisher 多載、
ES 生命週期、Domain mutator dispatch、測試／範例、相依、封裝及遷移文件。
這是本次實作的自我 code review，不宣稱獨立 reviewer 或全產品 binary compatibility 認證。

- 已修正遷移文件遺漏：中央版本管理、精確 Package ID source mapping、lock file、
  共用引用／using／容器還原設定，以及 host 必須接管 Configuration 的直接相依。
- 已補上舊本機 ES 候選的更名步驟、型別名稱序列化映射及 NuGet 相依最低版本與共同版號的區別。
- Consumer 改以六個精確 ID mapping 還原，驗證新 ID 及傳遞相依不依賴廣泛的前綴設定。
- 未發現需再修改核心 runtime 的阻擋問題；原本的來源／二進位破壞、metadata 預設忽略、
  ES 失敗後丟棄實例、通用 dispatcher 不可直接清除 ES 事件，均保留明確遷移說明。
- 發布的 visibility 落差與遠端保護設定屬下一階段發布工作，詳見 [CI/CD 現況與規劃](cicd-plan.md)。
