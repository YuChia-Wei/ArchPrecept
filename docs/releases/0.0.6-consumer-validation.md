# 0.0.6-preview 本機候選的 Domain 與 EventSourcing 採用結果

2026-11-25 使用本機 feed 的開發套件驗證。GitHub Packages 上的 [0.0.5-preview](0.0.5-preview.md) 及 [0.0.4-preview 的升級紀錄](0.0.4-consumer-validation.md) 各自保留原結果。

## Web API 的 identity 生命週期

從 dotnet-webapi-lab 的 `8bc05b8ac34f4edabeba9baa4d7f4ced3e3ad76e` 匯出隔離副本。兩次皆用 SDK 10.0.404、net10.0、相同的 34 個既有測試，以及相同本機封裝的 `ArchPrecept.Analyzers.Core`、`ArchPrecept.Contracts.Domain`、`ArchPrecept.Contracts.Application` 0.0.6-preview。三個還原套件的 SHA-256 與本機 feed 成品相符。為採用本版事件 API，兩次均讓會記錄領域事件的 OrderLine 繼承 `BufferedDomainEntity<Guid>`。

| SimpleDocumentEntity 新建路徑 | Domain／UseCase／HTTP 測試 |
|---|---|
| 保留隱含的無參數基底建構子 | 27 passed、7 failed。尚未指派就讀取 Id，HTTP 建立路徑回傳 500。 |
| 以 `base(0)` 明確初始化，其餘程式相同 | 34 passed、0 failed、0 skipped。 |

此模型用正整數識別已持久化文件，因此選用既有零值 sentinel。首次儲存指派正數，重建以原始正數恢復；已指派的 identity 拒絕改成另一個值。既有測試涵蓋建立、重建、儲存、事件分派成功及失敗，並檢查已持久化文件更換 identity 會失敗。產品仍拒絕讀取未初始化的 identity。可套用的範例見[套件使用指南](../package-usage.md#domain)。

測試以 managed DLL 執行（`UseAppHost=false`），採用隔離複本內的 mock／test repository。真實 ORM materialization、資料庫寫入、原生 AppHost 及下游原分支整合均未驗證。

## 事件能力與套件

使用 SDK 11.0.100 建置的本機 Domain／ES 套件執行[事件溯源範例](../../samples/EventSourcing/Program.cs)，在 net8.0、net10.0 均通過重播、pending、錯誤 commit、確認後重播等價檢查。儲存端以 `IESAggregateRoot<string>` 完成確認。還原的 XML 文件包含該介面的 `MarkChangesAsCommitted`、Domain 的 `IDomainEventSource.DomainEvents` 及 `IDomainEventBuffer` 的三個操作。

既有 Domain／ES 測試在兩個 TFM 各通過 26 項，涵蓋正常緩衝、版本不符、append 衝突及失效實例。append 衝突使用記憶體替身；產品的儲存端責任及公開契約差異見 [CT-005](../product/event-sourcing-contract.md)。

套件 consumer 的編譯器 SARIF 亦記錄兩筆 DBA1009：一筆來自 ES 參考基底的 `inherited-contract`，另一筆來自自有根的 `configured-contract`。兩者均在 When 之外直接指派狀態時回報，合法 override 內沒有回報。只延伸 `IESAggregateRoot<string>` 的儲存視圖對 transition 角色回報 `not-evaluated`。另以 Value Object 分別持有一般緩衝 Entity 及普通 Aggregate，兩個欄位都觸發 DBA1019。
